## 목표와 범위

막거나 패리해서 열리던 빈틈이 **확률로** 열리게 하고(상대의 값 × 날의 깎임 + 업그레이드의 덤), 사용자가 연습에서 날을 골라 직접 해 본 뒤 "덜 자주 파래지는가, 그래도 억울하지 않은가"를 답한다.

두 부분이다. **1부(실행 없이)**: 작업 0~8. **2부**: 작업 9(verifier) → 작업 10(playtester 한 번) → 작업 11(판정 판) → 작업 12(문서·커밋). 1부가 끝나면 묻지 않고 2부로 간다.

**확인할 결과**:

1. **확률은 데이터다**(원칙 5): 상대의 칸 둘(`opening_chance`, `opening_miss_limit`)과 `DuelRules`의 칸으로 정해지고, 셈은 순수 함수 하나(`DuelRules.opening_chance_for`)다.
2. **막은 순간에 안다**: 막힘·패리의 타격 순간에 열림(파란색, 지금 그대로)과 안 열림(낮은 비프, 상태 글자 자리의 글, 로그 한 줄, 바로 대기)이 갈린다. 예비 동작에는 아무 표시도 없다.
3. **모든 공격**: 단발·이어 베기·휩쓸기·큰 베기(버릇 반응)가 같은 확률을 탄다. 패턴은 끝에서 한 번만 굴린다.
4. **억울함을 줄이는 장치 셋**이 들어 있다: 안 열린 막기 직후의 반격은 값을 치르지 않는다(결정 402), 연속으로 안 열리는 횟수에 상한이 있고 화면이 알려 준다(결정 401), 패리는 확률에 덤을 받는다(결정 400 — 검토 전 물음 U1의 답대로).
5. **날과 업그레이드의 길이 이어져 있다**: 하루 모드의 `DuelRules` 사본에 날이 실리고, 업그레이드가 올릴 숫자 칸(`opening_chance_bonus`)이 있다. 하루의 상대는 값이 1.0이라 아직 아무것도 달라지지 않는다.
6. **견줘 볼 길**: 연습에서 "늘 열린다 / 1일차 / 2일차 / 3일차부터"를 골라 같은 상대와 해 본다.
7. **판 길이**(원칙 1): 봇 통계로 날마다의 평균 판 길이와 시간 초과의 수를 잰다(결정 405의 기준).
8. 하루의 결투는 그대로다(결정 396): 하루 데이터의 `git diff` 0줄, 기존 테스트가 통과한다(기대를 고치는 곳은 T81의 1 한 줄뿐, 결정 409).

1부에서는 1·5·8을 코드 읽기·값 대조·`git diff`로, 2·3·4·6을 코드 읽기와 테스트 작성으로 미리 본다. 테스트 통과와 7은 verifier, 화면과 소리는 playtester, 재미는 판정 판에서만 확인된다.

## 설계 결정

396. **범위는 "규칙·데이터의 칸·표시·연습의 고르기·통계"까지다. 하루에 값을 넣는 일은 036d다.** 날과 업그레이드가 걸린 규칙이지만 사용자가 먼저 답해야 하는 것은 "막았는데 안 열리는 맛이 괜찮은가"이고, 그것은 연습에서 날을 골라 보면 답할 수 있다. 하루에 넣으면 하루의 봇·테스트 기대 값(T13의 판 길이, 첫 피·깃털의 판들)이 한꺼번에 움직여 한 번에 확인할 크기를 넘는다. 지키는 길:
     - **상대의 확률 1.0은 "이 규칙이 꺼진 상대"다**: 날의 깎임도 타지 않고 난수도 부르지 않는다(올려 막기·공격 가방처럼 상대 데이터의 값 하나로 끈다). 스크립트의 기본값이 1.0이라 하루의 `.tres`는 한 줄도 바뀌지 않는다.
     - `DuelRules`의 새 칸은 이 계획에서 스크립트의 기본값으로만 둔다(`duel_rules.tres`는 그대로). 값을 `.tres`로 옮기는 것은 036d다.
     - 되돌리기 쉽다: 시험용 `.tres`의 `opening_chance` 두 줄을 지우면 전부 꺼진다.
397. **데이터의 꼴**(원칙 5).
     - `OpponentData`의 새 묶음 `@export_group("빈틈의 확률 (계획 036c)")`:
       - `opening_chance := 1.0` — 막힘·패리가 빈틈이 될 확률의 바탕(1일차, 업그레이드 없음). 1.0 이상이면 꺼짐.
       - `opening_miss_limit := 2` — 연속으로 안 열릴 수 있는 횟수의 상한. 그만큼 안 열렸으면 다음은 반드시 열린다. 0이면 상한이 없다.
       - `with_opening(chance: float) -> OpponentData` — `duplicate()` 뒤 `opening_chance`만 바꾼 사본(`flat()`과 같은 꼴. 연습과 통계가 쓴다).
     - `DuelRules`의 새 묶음 `@export_group("빈틈의 확률 (계획 036c)")`:
       - `opening_day_scale: Array[float] = [1.0, 0.85, 0.7]` — 날마다 바탕에 곱하는 값(1일차, 2일차, 3일차부터. 끝 값이 되풀이된다 — 평판의 `day_scale`과 같은 꼴).
       - `opening_chance_floor := 0.4` — 깎여도 이 아래로는 내려가지 않는다.
       - `opening_chance_bonus := 0.0` — 업그레이드가 더하는 칸(`UpgradeData`의 `property`가 가리킨다).
       - `parry_opening_bonus := 0.25` — 패리일 때 더하는 덤(결정 400).
       - `closed_counter_grace := 0.6` — 안 열린 막기 뒤 이 시간 안의 공격은 섣부른 공격이 아니다(결정 402).
       - `stage_day := 0` — 이 판의 날. 0이면 날이 없다(연습·자유 결투: 배율 1.0). `.tres`에 적는 값이 아니라 `DayState`가 사본에 싣는다(결정 406).
       - `opening_chance_for(base: float, day: int) -> float` — `base >= 1.0`이면 1.0. 아니면 `clampf(base × 배율(day) + opening_chance_bonus, opening_chance_floor, 1.0)`. 배율은 `day <= 0`이거나 배열이 비면 1.0, 아니면 `opening_day_scale[clampi(day − 1, 0, 크기 − 1)]`.
398. **굴림은 예비 동작이 시작될 때 한 번, 드러나는 것은 막은 순간이다.** 036b의 약속(난수는 예비 동작에서 한 번에. 결정 385)을 지키면서 사용자의 답("막은 순간에")을 따른다: 굴린 값은 뇌가 쥐고만 있고 화면·이벤트(`TELL_START`)에 싣지 않는다.
     - `OpponentBrain`의 새 변수: `opening_chance := 1.0`(이 판의 확률. 코어가 `setup`에서 `rules.opening_chance_for(opponent_data.opening_chance, rules.stage_day)`로 넣는다), `parry_opening_bonus := 0.0`(코어가 규칙의 값을 넣는다), `opening_roll := 0.0`, `closed_streak := 0`, `last_closed := false`.
     - `start_tell`의 **맨 끝**(높이를 다 뽑은 뒤)에서 `opening_chance < 1.0`일 때만 `opening_roll = rng.randf()`. 1.0이면 `rng`를 부르지 않는다 — 하루 데이터와 기존 테스트의 난수 차례가 그대로다(T87의 3). 확률이 1.0 아래인 상대는 예비 동작마다 정확히 한 번 부른다(맞거나 헛쳐서 쓰이지 않아도. 시드로 재현되게).
     - 뇌를 직접 만드는 기존 테스트는 기본값 1.0이라 그대로다.
399. **무엇에 걸리는가**: `resolve_strike`가 **막힘·패리로 회수가 0보다 크게 정해진 그때만** 본다. 열리는 조건은 `opening_chance >= 1.0` 또는 `opening_roll < opening_chance + (패리면 parry_opening_bonus)` 또는 상한(결정 401). 안 열리면 회수를 0으로 두고(바로 `start_idle`) `last_closed = true`, `closed_streak += 1`. 열리면 `closed_streak = 0`. `last_closed`는 `resolve_strike`가 불릴 때마다 먼저 거짓으로 되돌린다.
     - 패턴: 걸음이 남은 타격은 지금처럼 빈틈 없이 넘어간다(굴림을 보지 않는다). 마지막 타격에서 한 번 본다 — 패턴 하나에 굴림 하나.
     - 걸리지 않는 것(지금 그대로): 헛침의 회수(물러나서 헛치게 하는 것은 막기가 아니다), 무너짐, 버티기(본디 빈틈이 없다), 막힌 찌르기(`recovery_time` 0 — 본디 빈틈이 없다. 연속 수도 세지 않는다), 맞은 타격.
     - 결과 값은 그대로 `BLOCKED`·`PARRIED`다(`StrikeResult`에 값을 더하지 않는다). `STRIKE` 이벤트에 새 키 셋만 더한다: `closed: bool`, `closed_streak: int`(이 타격 뒤의 연속 수), `miss_limit: int`(상대의 상한). 있는 키의 값·차례는 그대로다(안 열린 타격은 `recovery` 0, `closed` 참).

400. **패리는 덤을 받는다**(U1의 사용자 답 A, 2026-11-25. `parry_opening_bonus` 0.25). 사용자의 "모든 공격"은 공격의 종류를 가르지 말라는 뜻이라 단발·패턴·큰 베기는 같은 확률을 탄다. **막는 솜씨**는 다른 축이다: 박자를 맞춰 새로 누른 막기(패리)가 들고 있던 막기와 똑같이 굴려지면 패리를 익힐 까닭이 줄고, 거꾸로 패리가 늘 열리면 패리를 하는 사람에게는 확률이 없는 것과 같아 "덜 자주 파래지게"가 사라진다. 그래서 가운데(+0.25)를 임시로 둔다. 값 하나(`parry_opening_bonus`)로 셋이 다 된다: 0.0 = 가르지 않는다, 0.25 = 덤, 1.0 = 패리는 늘 열린다. 휩쓸기에는 패리가 없어 덤도 없다(036 결정 372 그대로).
401. **연속 상한**: 연속으로 `opening_miss_limit`번(지금 2) 안 열렸으면 다음에 걸리는 막힘·패리는 굴림과 상관없이 열린다. 까닭 셋: 운이 나쁜 판의 길이에 끝이 생긴다(결정 405), 세 번 연달아 헛막는 억울함이 없다, 그리고 **읽을 수 있는 규칙이 된다**(원칙 4: "두 번 안 열렸으니 다음은 열린다"를 알고 반격을 준비한다). 그 사이에 맞거나 찌르기를 막아도 쌓인 수는 그대로다(보장은 쓰일 때까지 남는다). 화면이 알려 준다(결정 404). 0으로 끈다.
402. **안 열린 막기 직후의 반격은 값을 치르지 않는다.** 지금 규칙대로면 막자마자 누른 반격이 안 열린 판에서는 섣부른 공격이 되어 상대가 자세를 되찾는다 — "열렸는지 보고 나서 눌러라"가 되어 반응 싸움이다(원칙 4). 그래서 안 열린 타격의 시각부터 `closed_counter_grace`(0.6초) 동안 `is_rash_now()`가 거짓이다: 그 공격은 막히기만 하고 자세를 돌려주지 않는다. 코어의 새 변수 `_closed_until := -INF`(안 열린 `STRIKE`에서 `time + rules.closed_counter_grace`), `is_rash_now()`의 교전·밀착 갈래에 `and time >= _closed_until`. 런지 갈래는 건드리지 않는다. 막힌 공격의 내 회수 시간은 그대로 치른다(공짜는 아니다).
403. **맞물림**(전부 지금 규칙을 고치지 않는다):
     - 버릇("세 번 막히면 큰 베기"): 안 열린 막힘·패리도 연속 막힘으로 센다(`_count_blocked()`는 그대로 불린다). 안 열려도 막기는 큰 베기 쪽으로 한 걸음이다 — 헛일이 아니다.
     - 큰 베기(버릇 반응, 올려 막기): 같은 확률을 탄다(사용자 "모든 공격"). 올려서 받아냈는데 안 열리면 가장 아쉬운 자리라 판정 판 Q3에서 따로 묻는다. 버티기는 본디 빈틈이 없어 굴림과 무관하다.
     - 머리 지키기: `wide_open`은 회수가 시작될 때만 서므로 안 열린 타격에는 서지 않는다. 고칠 것이 없다.
     - 조건: `THROW_UNDETECTED`의 막은 수는 결과(막힘·패리)를 세므로 안 열려도 센다 — 타격 하나하나의 셈은 그대로다. `FIRST_BLOOD`·`TARGET_PART`는 닿은 공격만 본다. 판의 흐름(판 길이, 닿을 기회의 수)은 확률이 1.0 아래인 상대에서만 달라지고 하루에는 아직 그런 상대가 없다. 아직 없는 `DISARM`("패리 직후 공격 성공")은 패리의 빈틈에 기대므로 U1의 답이 그 조건의 어려움을 정한다 — BACKLOG에 적는다.
     - 방심·런지·엉킴·섣부른 공격의 되찾기: 건드리지 않는다(결정 402의 한 줄만).
404. **표시: 막은 순간에 눈·귀·글 셋으로 안다**(예비 동작에는 아무것도 없다).
     - 소리: 안 열린 막힘·패리는 `block`/`parry` 대신 새 음 `&"closed"`([260.0, 0.10] — 막힘 520Hz보다 한 옥타브 낮고 길다).
     - 상대 위의 글(`OpponentView._deflect_text`, "밀어붙임"과 같은 자리·시간): "틈을 안 준다". 이번으로 상한에 닿았으면 "틈을 안 준다 — 다음은 열린다". 판단은 이벤트의 새 키 `closed_streak`·`miss_limit`로 한다(뷰가 뇌를 다시 읽지 않는다).
     - 로그(`DuelHud._describe`): "막음 — 틈을 안 줬다" / "패리 — 틈을 안 줬다", 상한에 닿았으면 뒤에 " (다음은 열린다)".
     - 열린 쪽은 지금 그대로다(파란색, "막음"·"패리!"·"받아냄!").
     - 막는 법 한 줄 `DuelHud.HELP_OPENING` = " · 막아도 틈을 안 줄 때가 있다(낮은 소리). 두 번 안 주면 다음은 반드시 열린다" — `help_text`는 상대의 확률이 1.0 아래일 때만 붙인다(하루의 상대에는 붙지 않는다). "두 번"은 상대의 `opening_miss_limit`로 채우고, 0이면 뒤 문장을 뺀다.
     - 디버그 글(`_debug_label`)에 이 판의 확률과 연속 수 한 줄. 확률의 숫자는 그 밖의 화면에 보이지 않는다(흥정의 확률과 같은 대접. 사용자 결정 2026-11-20의 선례).
405. **시험 값과 판 길이**(전부 임시).

     | | 바탕 | 1일차 | 2일차 (×0.85) | 3일차부터 (×0.7) | 3일차 + 덤 0.15 |
     |---|---|---|---|---|---|
     | 바르톨로 (시험용) | 0.80 | 0.80 | 0.68 | 0.56 | 0.71 |
     | 브루노 (시험용) | 0.75 | 0.75 | 0.6375 | 0.525 | 0.675 |

     - 바닥 0.4, 상한 2, 패리 덤 0.25. 업그레이드 하나가 올리는 양은 0.15로 잡는다(하루쯤 되돌리는 크기: 3일차의 0.56 → 0.71이 2일차의 0.68 언저리다). 물건과 값(값 120 안팎, 갈래는 훈련)은 036d에서 정한다.
     - 손 셈(상한 2, 들고 막기만): 걸리는 막기 가운데 열리는 몫은 1 / (1 + q + q²), q = 1 − 확률. 0.80 → 0.81, 0.68 → 0.70, 0.56 → 0.61, 바닥 0.40 → 0.51. 상한이 있어 어떤 값에서도 1/3 아래로 내려가지 않는다. 빈틈이 드물어지는 만큼 판이 길어진다: 3일차는 "늘 열린다"보다 빈틈까지 걸리는 시간이 1.6~1.7배, 바닥에서도 2배쯤이다(판 전체는 다가서기·무너짐·마무리가 섞여 그보다 덜 늘어난다).
     - 판 길이를 지키는 기준(작업 9의 봇 통계, 들고 막는 봇): **3일차 설정의 평균 판 길이가 "늘 열린다"의 1.7배 이하이고, 시간 초과로 끝난 판의 몫이 "늘 열린다"보다 20%p 넘게 늘지 않는다.** 넘으면 이 계획 안에서 한 번 고친다 — `opening_day_scale`의 끝 값이나 바닥을 올린다(회수 시간·제한 시간은 건드리지 않는다). 그래도 넘으면 수와 함께 사용자에게 가져간다(판정 판 Q2).

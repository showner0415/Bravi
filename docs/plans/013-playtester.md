# 계획 013: 다시 호출할 수 있는 플레이테스터

- 버전: v2
- 개발 단계: 2단계 하루 루프의 플레이 검증 지원
- 근거: 사용자가 Bravi 프로젝트에서 계속 호출할 플레이 테스트 에이전트를 요청했다.

## 목표

Claude Code가 프로젝트 역할 `playtester`를 이름으로 호출해 현재 빌드에서 지정한 기능을 직접 플레이하고 관찰 결과를 받을 수 있다.

## 범위

프로젝트의 에이전트 정의와 호출 방법을 기록한다.

## 범위 밖

게임 구현, 테스트 코드 추가, 정기 실행, 이번 설정 작업 중 게임 재실행.

## 작업 목록

1. `CLAUDE.md` 11장의 역할 표에 플레이테스터를 추가한다. 호출 요청 예시와 메인이 전달할 기능 또는 재현 경로를 적고, 기존 계획 승인 절차와 별개로 실행 검증을 맡긴다는 점을 확인한다.
2. 기존 역할처럼 YAML frontmatter와 Markdown 본문을 사용해 `.claude/agents/playtester.md`을 작성한다. 게임 실행 확인을 요청받으면 `play.ps1`로 현재 프로젝트의 게임 창을 열고 실제 입력과 화면 반응으로 확인한다. 일반 점검은 타이틀 → 카운터 → 결투 → 정산으로 진행하고, 특정 기능 요청이면 해당 기능까지 플레이한다. 의뢰 조건과 정산 결과가 연결되는지 살피고, 로그의 오류·경고 및 재현 절차를 보고한다. GUI 접근이 막히면 이유와 미확인 범위를 알린다. 기존 자동 테스트는 필요한 경우 보조 근거로 사용한다. 게임 소스 수정 없이 자신이 연 게임 창을 종료한다.
3. YAML frontmatter의 `name`, `description`, 실제 실행에 필요한 도구 접근 및 Markdown 본문의 역할 지시를 확인하고 호출 예시의 역할명과 대조한다. 현재 설치본의 `claude agents`는 백그라운드 세션 관리 명령이다. Claude Code의 프로젝트 역할 목록을 새로 읽을 수 있으면 게임 실행 없는 짧은 역할 확인으로 검증한다. 현재 세션의 등록 확인이 어려우면 파일 검증 결과와 실제 호출 여부를 구분해 보고한다.

## 설계 결정

프로젝트에 역할 정의를 보관한다. 사용자가 호출할 때마다 해당 빌드와 요청 범위로 점검할 수 있다. 게임 설계의 미정 사항은 없으며 역할 설정은 독립적으로 수정할 수 있다.

## 위험

자동 테스트만으로는 화면 잘림이나 입력 반응을 판정하기 어렵다. 직접 본 화면과 자동 검사 결과를 구분해 기록한다.

## 작업 목록

순서는 "규칙이 숫자로 맞는지 → 손으로 쳐 볼 수 있는지 → (사용자 중간 확인) → 의뢰가 갈리는지" 순이다.

**실행·판정 공통 규칙** (모든 작업의 "완료 확인"에 적용)

- 테스트 명령은 항상 한 쌍으로 돌린다: `<godot> --headless --path C:\godot\bravi --import` 다음에 `<godot> --headless --path C:\godot\bravi --script res://tests/run_tests.gd --quit-after 6000`.
- 통과 판정은 종료 코드만으로 하지 않는다. 세 가지를 모두 본다: 종료 코드 0, 출력 마지막 줄이 `ALL PASS n/n`(n은 그 작업까지의 기대 개수), 출력에 `SCRIPT ERROR`와 `ERROR:`가 없음. `--import`와 씬 스모크 실행도 출력 문자열로 판정한다.
- `--quit-after`는 시간이 아니라 메인 루프 반복 횟수다. 테스트는 실시간을 기다리지 않는다. 코어는 `tick`을, 씬은 `advance(delta)`를 루프에서 직접 불러 시간을 흘린다.
- 씬 스모크 실행도 `--headless`로 돌린다(사용자 화면에 창이 뜨지 않는다).
- Godot 4.4 이상이 만드는 `.gd.uid` 파일은 커밋 대상으로 둔다.

### 작업 2. 타입과 Resource 스크립트

- 무엇 (전부 `class_name` 있는 GDScript, 수치는 전부 `@export`):
  - `scripts/duel/duel_types.gd` — enum `Direction{LEFT, CENTER, RIGHT}`, `Height{HIGH, MID, LOW}`, `Distance{FAR, ENGAGE, CLOSE}`, `Part{HEAD, HAT, TORSO, SWORD_ARM, SWORD_HAND, LEGS}`. enum 값은 `.tres`에 정수로 저장되므로 **끝에만 추가하고 재정렬하지 않는다**
  - `scripts/duel/duel_rules.gd` (`DuelRules`) — 제한 시간, 플레이어 자세 최대값
  - `scripts/duel/weapon_data.gd` (`WeaponData`) — 찌르기/베기 예비 시간, 상단 배율, 공격 후 회수, 패리 창, 막기 재입력 쿨다운, 간격 이동 시간, 밀착 예비 배율
  - `scripts/ai/attack_data.gd` (`AttackData`) — 이름, 방향, 예비 시간, 회수 시간, 선택 가중치, 큰 공격 여부, 예비 동작 포즈(팔 오프셋, 칼 회전, 색). 포즈 필드는 4단계에서 애니메이션 이름으로 대체될 임시 필드다
  - `scripts/ai/habit_data.gd` (`HabitData`) — 트리거 enum(1단계는 `BLOCKED_STREAK`만 구현), 횟수, 반응 공격(`AttackData`), 설명 문구
  - `scripts/ai/opponent_data.gd` (`OpponentData`) — 이름, 칼 든 쪽, 자세 최대값, 무너짐 시간, 무너짐 뒤 회복 자세, 대기 시간 범위, 접근 지연, 일반 공격 목록, 버릇 목록, 패리당했을 때 회수 추가 시간, 헛쳤을 때 회수 배율, 밀착 예비 배율
  - `scripts/commission/commission_condition.gd` (`CommissionCondition`, 기반 클래스) — 메서드 5개:
    - `describe() -> String` 의뢰 선택 화면과 HUD에 쓰는 조건 설명
    - `check_end(record) -> 종료 사유 또는 없음`
    - `evaluate(record) -> int` 충족도 0~100. 종료된 `record`에 대해서만 의미가 있다
    - `explain(record) -> Array[String]` 결과 화면의 항목별 내역
    - `live_meter(record) -> Dictionary` 결투 중 HUD 게이지. 기본 구현은 빈 Dictionary(게이지 없음). 있으면 `{label: String, value: int 0~100, pending: int}`
  - `scripts/commission/commission.gd` (`Commission`) — CLAUDE.md 4장 필드 그대로: `client_name`, `dialogue`, `opponent`, `conditions: Array[CommissionCondition]`, `base_reward`, `tip_max`, `reputation_effect`
- 규칙: `CommissionCondition` 하위 클래스는 내부 상태를 갖지 않는다(판단 근거는 전부 `record`). `OpponentBrain`은 `OpponentData`의 배열을 수정하지 않는다. Resource는 로드 캐시로 공유되므로, 이 규칙이 깨지면 R 재시작 때 이전 판 상태가 샌다.
- 완료 확인: `--import` 출력에 오류 없음. 실제 검증은 작업 3, 5의 테스트에서 한다.

### 작업 3. 결투 규칙 코어와 상대 두뇌 (씬 없이)

- 무엇:
  - `scripts/duel/duel_record.gd` (`DuelRecord`, RefCounted) — 시각이 붙은 이벤트 목록(공격 판정, 막기, 패리, 간격 변경, 스침과 유효타의 대상·부위, 플레이어가 맞았을 때의 상황, 무너짐)과 경과 시간, 종료 사유
  - `scripts/ai/opponent_brain.gd` (`OpponentBrain`, RefCounted) — 상태 `IDLE → TELL → ATTACK → RECOVERY`와 `STAGGER`, 가중치로 다음 공격 선택, 버릇 판정. 난수는 주입받은 `RandomNumberGenerator`만 쓴다
  - `scripts/duel/duel_core.gd` (`DuelCore`, RefCounted) — 아래 "결투 규칙 v1"의 구현. Node에 의존하지 않는다. 입력 메서드(`set_aim(direction, height)`, `press_attack()`, `set_guard(bool)`, `step(±1)`)와 `tick(delta)`, 이벤트 시그널. 예비 동작 시작 이벤트는 예정 타격 시각을 함께 내보낸다. 조건 목록이 없으면 "어느 쪽이든 유효타 또는 시간 초과로 종료"되는 자유 결투다
  - `data/duel_rules.tres`, `data/weapons/rapier.tres`, `data/opponents/opponent_01.tres` — "초기 수치" 표의 값
  - `tests/duel_bots.gd` — 테스트용 플레이어 봇. 입력은 **절대 시각이 아니라 코어 이벤트에 반응해** 넣는다(예비 시작 이벤트를 받으면 막기, 회수 시작 이벤트를 받으면 공격, 패리는 예정 타격 시각 0.10초 전을 지난 첫 tick에 누름). 규칙 테스트에서는 상대의 공격 순서를 테스트용 `OpponentData`로 고정하고, 판 길이 시뮬레이션에서는 실제 `opponent_01.tres`와 시드 난수를 쓴다
- 완료 확인: 테스트 실행에서 `ALL PASS 14/14` (T0~T13).
  - T1 방어: 올바른 방향 막기 → 자세 변화 없음 / 틀린 방향 → 스침당함, 내 자세 −1, 결투 계속, 상대는 회수 없이 `IDLE` / 내 자세 0에서 한 번 더 실패 → 유효타로 패배 종료
  - T2 받아치기: 막힌 베기 뒤 중단 찌르기 → 몸통 스침, 상대 자세 −1, 회수가 그 시각에 끝남 / 막힌 찌르기 뒤 중단 찌르기 → 막힘, 자세 변화 없음
  - T3 막힌 베기 뒤 상단 베기: 교전에서는 닿지 않음 / 밀착에서는 모자 스침
  - T4 패리: 패리당한 베기 뒤 상단 베기 → 모자 스침 / 패리당한 찌르기 뒤 중단 찌르기 → 스침, 상단 베기 → 닿지 않음
  - T5 버릇: 연속 3회 막으면 다음 공격이 큰 베기, 큰 베기를 막은 뒤 상단 베기 → 모자 스침 / 스침당하면 연속 횟수가 0으로 / 헛침은 횟수를 바꾸지 않음

  - 찌르기는 받아칠 수 없고 베기는 받아칠 수 있다는 것을 플레이하며 알아챌 수 있는가
  - 밀착에서도 읽히는가, 반응 속도 싸움이 되는가
  - 대기 중 공격이 전부 막히는 것이 답답한가
- B. 의뢰 차이
  - 첫 피 / 깃털 / 지기에서 하는 행동이 실제로 달라지는가, 점수만 다른가
  - 깃털을 **밀착 없이 / 밀착으로** 각각 해 본다. 밀착 경로가 첫 피와 같은 플레이(조준 칸만 다름)로 느껴지는가. 그렇다면 상대 밀착 배율을 0.65~0.7로 낮춰 다시 해 본다
  - 깃털에서 몸을 건드려 빨리 끝내고 싶은 유혹이 생기는가, 감점(스침 −10)이 그 선택을 고민하게 만드는가
- C. 판 길이와 리듬
  - 결과 화면의 결투 시간을 "예상 판 길이"와 비교해 적는다
  - 자세를 14칸 깎는 동안 같은 동작의 반복으로 느껴지는가, 쌓아 가는 맛이 있는가
  - 찌르기만 연달아 올 때 기다리는 것이 지루한가, 긴장되는가
  - 무너뜨린 순간과 마무리가 보상으로 느껴지는가
  - 내 자세 3칸은 너그러운가, 빡빡한가
- D. 버릇을 대사 힌트와 관찰로 알아챌 수 있는가
- E. 지기 — 의심 게이지가 오르는 이유를 납득할 수 있는가. 요령을 알고 난 뒤 두세 판째에도 재미있는가
- F. 조작
  - 우클릭을 누른 채 마우스만 옮기는 플레이가 지루한가
  - W/S를 누를 이유가 있었는가
  - 멀리에서 타격 직전에 W로 들어가 헛친 공격의 빈틈을 치는 것(결정 19)이 실제로 되는가, 쓸 만한가, 막아야 한다고 느끼는가

## 결투 규칙 v1

수치는 전부 `.tres`에 있고 조정 대상이다.

### 핵심: 자세

- 상대와 플레이어는 각각 **자세** 수치를 가진다(상대 14, 플레이어 3). 화면에 칸으로 보인다.
- 자세가 남아 있는 쪽에게 닿은 공격은 **스침**이다. 피가 나지 않고 결투가 끝나지 않으며, 맞은 쪽의 자세가 1 깎인다.
- 자세가 0인 쪽에게 닿은 공격이 **유효타**다. 의뢰의 "첫 피", "깃털 자르기"는 유효타로만 이루어진다.
- 상대의 자세를 깎는 방법은 **닿는 것 하나뿐**이다. 막기와 패리는 자세를 깎지 않고, 닿을 수 있는 빈틈을 만든다.
- 한 빈틈에는 한 번만 닿는다(스침이 들어가면 상대는 물러나 그 회수가 끝난다).

### 시간 처리

- 코어는 자체 시계(초)를 가진다. 모든 상태의 종료 시각은 **시작 시각 + 길이**로 미리 계산해 두고, `tick(delta)`은 시계를 delta만큼 올린 뒤 그 사이에 지난 전이를 시각 순으로 처리한다. 초과분은 다음 상태로 이월된다.
- 판정은 tick 시각이 아니라 예정 시각끼리 비교한다. 같은 시각에 겹친 전이는 상대 쪽을 먼저 처리한다. "회수 종료 시각보다 앞"은 엄격 비교다(같으면 닿지 않음).
- 이벤트 시그널은 tick 안에서 모아 두었다가 전이 처리가 끝난 뒤 순서대로 내보낸다. 시그널 핸들러가 입력 메서드를 불러도 처리 도중의 상태가 바뀌지 않는다.
- 입력은 받은 즉시 현재 코어 시계의 시각으로 적용한다. 입력만 최대 1 tick 늦게 양자화된다. "여유 0.1초" 조건은 delta 1/30의 3 tick이다.

### 상대 타임라인

```
IDLE (대기 시간) → TELL (예비 시간) → [타격 순간] → RECOVERY (회수 시간) → IDLE
                                                    자세 0이 되면 → STAGGER (무너짐 시간) → IDLE
```

- **타격 순간은 `TELL`이 끝나는 시각이다.** `ATTACK` 상태는 길이 0으로, 그 시각에 방어 판정만 한다.
- 타격 판정 순서: ① 간격이 멀리면 플레이어 상태와 무관하게 **헛침** ② 플레이어가 `GUARD`이고 방향이 맞으면 **막힘** 또는 **패리** ③ 그 밖에는 **닿음**(플레이어 자세가 남았으면 스침, 0이면 유효타로 패배).
- 타격 결과별 회수 시간: 막힘 = 공격의 회수 시간 / 패리당함 = 회수 시간 + 패리 추가 / 헛침 = 회수 시간 x 헛침 배율 / **닿음 = 0** (플레이어에게 닿은 공격 뒤에는 빈틈이 없다).
- **상대는 `RECOVERY`와 `STAGGER` 동안에만 닿는다.** 플레이어 공격의 판정 시각(예비가 끝나는 시각)이 그 상태의 종료 시각보다 앞이면 닿음, 아니면 막힘. `IDLE`/`TELL` 중의 공격은 전부 막히고 자세도 깎이지 않는다.
- `RECOVERY`에서 닿으면: 스침. 상대 자세 −1, 그 시각에 회수가 끝나 `IDLE`로 간다. 자세가 0이 됐으면 `IDLE` 대신 `STAGGER`로 간다.
- `STAGGER`에서 닿으면: 유효타. 상태는 바뀌지 않는다(무너짐 시간 안에는 여러 번 맞을 수 있다). 무너짐 시간이 끝나면 자세가 회복값으로 돌아오고 `IDLE`.
- 예비 시간에 붙는 밀착 배율은 `TELL`을 시작하는 순간의 간격으로 정하고 도중에 바뀌지 않는다.
- 다음 공격은 일반 공격 목록에서 가중치로 고른다. 간격이 멀리이면 `TELL`을 시작하지 않는다. "간격이 멀리이고 상대가 `IDLE`"인 상태가 접근 지연만큼 이어지면 간격을 교전으로 바꾸고 대기 시간을 새로 잰다. 둘 중 하나가 깨지면 접근 지연을 처음부터 다시 잰다.

### 플레이어 상태

| 상태 | 길이 | 받는 입력 | 타격이 닿으면 기록되는 상황 |
|---|---|---|---|
| `READY` | — | 공격 → `WINDUP` / 막기 누름 → `GUARD` / W·S → `STEPPING` | `UNGUARDED` |
| `WINDUP` | 공격 예비 시간 | 없음 (취소·막기·이동 불가) | `IN_ATTACK` |
| `RECOVER` | 공격 후 회수 | 없음 | `IN_ATTACK` |
| `GUARD` | 우클릭을 누르는 동안 | 공격 → `WINDUP`(막기 풀림) / 뗌 → `READY` | 방향이 틀렸을 때 `WRONG_GUARD` |
| `STEPPING` | 간격 이동 시간 | 없음 | `UNGUARDED` |

- 공격: 좌클릭 순간의 방향·높이·간격으로 부위와 예비 시간이 고정된다. 예비가 끝나는 시각에 판정: 간격이 멀리면 헛침, 상대가 `RECOVERY`/`STAGGER`면 닿음, 아니면 막힘. 그 뒤 `RECOVER`.
- 스침당해도 플레이어의 상태는 바뀌지 않는다(경직 없음). 진행 중인 `WINDUP`은 그대로 이어진다.
- 막기 방향은 `GUARD` 동안 마우스를 따라 바뀐다. 판정에는 타격 순간의 방향을 쓴다.
- 패리: `GUARD`에 **새로 누름으로** 들어온 시각이 타격 순간 전 패리 창 안이고 방향이 맞음.
- 막기 재입력 쿨다운: `GUARD`를 벗어나면(뗌이든 공격이든) 쿨다운이 돈다. 쿨다운 안의 누름은 받지 않는다. 쿨다운이 끝났을 때 아직 누르고 있으면 `GUARD`로 들어가되 "새로 누름"으로 치지 않는다(패리 불가). `WINDUP`/`RECOVER`/`STEPPING`이 끝났을 때 누르고 있는 경우도 같다.
- 간격 이동: 목표 간격은 누른 순간의 간격 ±1로 고정되고, 간격 값은 `STEPPING`이 **끝나는 시각**에 목표로 바뀐다. 범위를 벗어나는 이동은 무시한다.

### 조준

마우스 가로 3등분 = 방향(왼쪽 베기 / 찌르기 / 오른쪽 베기), 세로 3등분 = 높이(상/중/하). 방향은 화면 기준이다(상대의 "왼쪽 베기" = 플레이어 화면 왼쪽으로 들어옴). 조합이 노리는 부위를 정한다. 이 표는 코어 안에 const 하나로만 둔다.

| 높이 | 찌르기 | 상대 칼 든 쪽 베기 | 반대쪽 베기 |
|---|---|---|---|
| 상 | 머리 | 모자 | 모자 |
| 중 | 몸통 | 칼 든 팔 | 몸통 |
| 하 | 다리 | 다리 | 다리 |

칼 든 손은 노드와 enum만 있고 조준 대상이 아니다. 상단은 예비 시간이 길다(정밀 조준의 대가).

### 간격

양쪽이 공유하는 값 하나. 결투는 멀리에서 시작.
- 멀리: 양쪽 공격 모두 헛침. 헛친 공격은 회수가 짧아진다. 물러나는 것은 안전하지만 반격 기회를 거의 주지 않는다
- 교전: 기본
- 밀착: 상대 예비 시간과 내 공격 예비 시간이 각각의 배율로 짧아진다. 읽을 시간이 줄어드는 대신 막힌 베기의 회수 창에도 상단 베기가 들어간다

### 버릇

상대 공격이 연속 3회 막히면(막기·패리 모두) 다음 공격은 반드시 큰 베기다. 큰 베기가 나가면 횟수를 0으로 되돌린다. 플레이어에게 닿은 공격과 무너짐도 횟수를 0으로 되돌린다. 헛침은 횟수에 더하지도 되돌리지도 않는다.

### 종료

플레이어가 유효타를 맞음(패배), 제한 시간 경과, 또는 의뢰 조건의 `check_end`. 조건이 없는 자유 결투는 상대가 유효타를 맞아도 끝난다.

### 빈틈 창과 여유 (T11이 검사하는 것)

조건: 아래 표의 모든 조합에서 예비 시간(이동이 필요하면 이동 시간 포함)과 창의 차이가 0.1초 이상이어야 한다. 수치를 조정할 때도 이 조건을 지킨다.

| 빈틈 | 창 | 닿는 공격 (여유) | 닿지 않는 공격 (여유) |
|---|---|---|---|
| 막힌 찌르기 | 0.00s | 없음 | 전부 (가장 빠른 밀착 찌르기 0.12s, 0.12) |
| 막힌 베기 | 0.55s | 중단 찌르기 0.20 (0.35), 중단 베기 0.35 (0.20), 상단 찌르기 0.40 (0.15), 밀착 상단 베기 0.42 (0.13) | 상단 베기 0.70 (0.15) |
| 패리당한 찌르기 | 0.55s | 위와 같음 | 상단 베기 0.70 (0.15) |
| 패리당한 베기 | 1.10s | 상단 베기 0.70 (0.40) | — |
| 큰 베기(막힘) | 1.60s | 상단 베기 0.70 (0.90) | — |
| 헛친 베기 (타격 뒤 전진) | 0.30s | 없음 | 전진 0.30 + 찌르기 0.20 = 0.50 (0.20) |
| 헛친 큰 베기 (타격 뒤 전진) | 0.88s | 전진 + 찌르기 0.50 (0.38), 전진 + 상단 찌르기 0.70 (0.18) | 전진 + 상단 베기 1.00 (0.12) |
| 무너짐 (마지막 스침 뒤) | 1.50s | 내 회수 0.30 + 상단 베기 0.70 = 1.00 (0.50) | — |

T11의 범위는 이 표의 행이다. 빈틈 안에서 일부러 간격을 옮긴 뒤 치는 조합(예: 막힌 베기 창에서 전진 0.30 + 밀착 중단 베기 0.21 = 0.51)은 넣지 않는다. 경계에 가깝지만 사람이 낼 수 없고, 같은 창에 이동 없이 더 빨리 닿는 공격이 있어 이득도 없기 때문이다.

이 수치에서:
- **몸에 닿는 길**(작은 빈틈으로 충분): 베기를 막고 받아치기 / 아무 공격이나 패리하고 받아치기 / 큰 베기 받아내기.
- **모자에 닿는 길**(큰 빈틈이 필요): 베기를 패리 / 큰 베기 받아내기 / 밀착에서 베기를 막기. 교전 거리에서 막기만 해서는 큰 베기 때만 닿는다.

### 예상 판 길이 (초기 수치 기준)

상대 공격은 "일반 3회 + 큰 베기 1회"의 묶음으로 돈다(전부 막을 때). 한 묶음은 약 9초다. 교환 한 번은 찌르기 약 1.9초, 베기 약 2.3초, 큰 베기 약 2.7초(대기 평균 1.25초 포함, 받아치기는 타격 0.3초 뒤에 닿는다고 가정). 자세 14칸을 깎은 뒤 마무리 한 번이 필요하다.

| 의뢰 | 플레이 | 묶음당 깎는 칸 | 예상 길이 |
|---|---|---|---|
| 첫 피 | 전부 패리하고 받아치기 (가장 빠름) | 4 | 약 35초 (대기 운이 가장 좋으면 약 30초) |
| 첫 피 | 막기만, 베기와 큰 베기 뒤에 받아치기 | 평균 2.2 | 약 58초 (대략 45~75초) |
| 깃털 | 밀착에서 전부 패리하고 모자 치기 | 4 | 약 37초 |
| 깃털 | 밀착에서 막기만, 베기와 큰 베기 뒤에 모자 치기 | 평균 2.2 | 약 58초 |
| 깃털 | 교전에서 베기를 패리, 큰 베기 받아내기 | 평균 2.2 | 약 66초 |
| 깃털 | 교전에서 막기만 (큰 베기 때만 닿음) | 1 | 약 126초 → **시간 초과** |
| 지기 | 30초를 넘기고 네 번 맞기 | — | 약 31~40초 |

- 숙련 플레이는 모두 30~90초 안에 든다. 의도한 길에서 벗어난 플레이(깃털을 교전에서 막기만) 하나가 시간 초과가 난다. 깃털에서 몸을 스치면 칸은 빨리 깎이지만 한 번에 10점을 잃는다.
- 이 표는 손 계산이다. T13과 T20이 실제 `.tres`와 시드 30개로 같은 값을 시뮬레이션해 출력하고 범위를 검사한다.

## 조건 판정 v1

| 조건 | 결투가 끝나는 때 | 충족도 |
|---|---|---|
| `FIRST_BLOOD` | 상대의 머리·몸통·팔·다리에 유효타 1회 | 몸통·팔·다리 100 / 머리 40 / 패배·시간 초과 0. 스침은 점수에 영향 없음 |
| `TARGET_PART`(모자) | 모자에 유효타(깃털 잘림) | 100 − 10 x (다른 부위 스침 수) − 30 x (다른 부위 유효타 수), 최저 0 / 모자를 못 자르고 끝나면 0. 모자 스침은 감점 없음. 다른 부위 유효타로는 결투가 끝나지 않는다 |
| `THROW_UNDETECTED` | 플레이어가 유효타를 맞음(목표) 또는 상대 유효타(실패) | 패배 시 100 − 의심도 / 이기거나 시간 초과면 0 |

`FIRST_BLOOD`와 `TARGET_PART`의 `live_meter`는 비어 있다(게이지 없음).

### 의심도 (0~100, 수치는 조건 Resource의 `@export`)

| 항목 | 가산 | 확정 시점 | 게이지 |
|---|---|---|---|
| 맞을 때마다 그 상황: `UNGUARDED` +20 / `WRONG_GUARD` +5 / `IN_ATTACK` +0 | 진행 중 누적 | `value` |
| 교전·밀착에서 공격 없이 6초가 찰 때마다 | +15 | 진행 중 누적 | `value` |
| 멀리에 머문 누적 시간이 8초를 넘은 뒤 | 초당 +5 | 진행 중 누적 | `value` |
| 30초 안에 패배 | +30 | 종료 시 확정 | `pending` (30초가 지나면 사라짐) |
| 막아낸 횟수 4회 미만 | +20 | 종료 시 확정 | `pending` (4회 막으면 사라짐) |
| 상대에게 닿은 횟수 2회 미만 | +15 | 종료 시 확정 | `pending` (2회 닿으면 사라짐) |

- 지려면 네 번 맞아야 한다(스침 3회 + 유효타 1회). 맞을 때마다 그 상황이 의심도에 더해진다.
- "공격 없이 6초"의 시계는 교전·밀착에 있는 동안만 흐르고, 교전·밀착에서 낸 공격의 판정 시각에 0으로 돌아간다. 멀리에서는 멈출 뿐 돌아가지 않는다. 멀리에서 낸 공격은 공격으로 세지 않는다.
- `live_meter.value` = 누적 항목의 합(최대 100). 줄어들지 않는다. `pending` = 지금 패배하면 더해질 종료 시 확정 항목의 합. 줄어들 수 있다.
- 종료 후 의심도 = `min(100, value + 종료 시 확정 항목 합)`. 결과 화면의 `explain`은 항목을 각각 한 줄로 보여 준다.

### 세 의뢰가 요구하는 행동

- **첫 피**: 가장 쉬운 빈틈(베기를 막고 중단 찌르기)으로 몸을 스쳐 자세를 깎고, 무너지면 찌른다. 패리를 섞으면 찌르기도 기회가 되어 빨라진다.
- **깃털**: 쉬운 빈틈을 쓸 수 없다. 몸을 스치면 감점이므로 모자에 닿을 만큼 큰 빈틈만 골라 써야 한다. 패리를 하거나, 밀착의 위험을 지거나, 큰 베기를 기다린다. 급하면 점수를 내주고 몸을 스칠 수 있다.
- **지기**: 30초 넘게 제대로 싸우는 모습을 보이고(막기 4회, 닿기 2회, 6초마다 공격), 네 번을 그럴듯하게 맞는다. 상대를 무너뜨리고 찌르면 이겨 버려 실패다.

## 위험

- **메인 에이전트는 손맛을 확인할 수 없다.** 헤드리스 테스트는 규칙의 경계, 점수 계산, 봇의 판 길이만 보증한다. 1단계 완료 기준은 사용자 플레이로만 판단된다. 대비: 작업 4 뒤 중간 확인, 체크리스트, 수치 전부 `.tres`.
- **자세 14칸이 같은 동작의 반복으로 느껴질 수 있다**("막고 클릭"을 14번). 이 구조의 가장 큰 위험이다. 대비: 중간 확인의 체크리스트 C. 반복으로 느껴지면 칸 수를 줄이는 것만으로는 원칙 1과 다시 충돌하므로, 교환에 변화를 주는 장치(연속 공격 묶음, 감정 상태)를 다음 계획에서 검토한다.
- **판 길이가 운에 따라 넓게 퍼진다.** 막기만 하는 플레이는 베기가 몇 번 나오느냐에 따라 45~75초로 갈린다. 가장 빠른 플레이는 대기 운이 좋으면 30초에 걸친다. 대비: T13·T20이 분포를 출력, 자세 최대값 ±2 조정 허용.
- **깃털을 교전에서 막기만 하면 시간 초과가 난다.** 처음 하는 사람은 왜 자세가 안 깎이는지 모를 수 있다. 대비: 의뢰 대사의 힌트 두 줄, 조준 부위 강조, "닿지 않음" 사건 표시, 체크리스트 B.
- **밀착 경로의 깃털이 첫 피와 같은 플레이가 될 수 있다**(W 한 번 + 베기 막기 + 위 칸 클릭). 대비: 체크리스트 B에서 두 경로를 따로 확인, 상대 밀착 배율을 0.65~0.7로 낮추는 조정안. 낮추면 밀착 찌르기 예비가 0.42~0.46초가 되어 원칙 4와 부딪칠 수 있으니 중간 확인 결과를 보고 정한다.
- **패리가 화면으로 읽히지 않을 수 있다.** 대비: 연속 이동, 고리와 고정 띠, 조작 안내 한 줄. 그래도 외워서 맞추게 되면 표시 방식을 다음 계획에서 고친다.
- **지기 의뢰의 정답이 하나로 굳을 수 있다**(막고 두 번 스친 뒤, 30초가 지나면 공격하다 맞기를 네 번). 대비: 체크리스트 E. 1단계에서는 고치지 않는다.
- **대기 중 공격이 전부 막혀 공격 주도권이 없다고 느껴질 수 있다**(결정 5). 대비: 체크리스트 A.
- **막기를 누른 채 방향만 옮기는 것이 안전한 기본 플레이가 된다.** 패리를 노릴 때만 뗐다 눌러야 한다. 대비: 체크리스트 F.
- **자세 구조는 CLAUDE.md 3장에 없는 규칙이다**(자세 수치, 무너짐 상태, 스침과 유효타의 구분). 대비: 보고서 4번에서 CLAUDE.md 반영 여부를 사용자에게 묻는다. 메인 에이전트가 임의로 CLAUDE.md를 고치지 않는다.
- **손으로 쓴 `.tres`/`.tscn`이 로드되지 않을 수 있다.** 타입 배열은 `Array[ExtResource("id")]([...])` 형식이 필요하다. 대비: T15가 배열 길이와 원소 타입까지 검사. 계속 막히면 일회용 스크립트에서 `ResourceSaver.save()`로 생성한다.
- **테스트 러너가 끝나지 않을 수 있다**(GDScript 런타임 오류는 해당 함수만 중단시킴). 대비: `--quit-after` 안전장치, 통과 판정을 `ALL PASS n/n` 문자열로.
- **`--script` 실행에서 오토로드가 뜨는지는 확인하지 못했다.** 대비: 테스트와 `duel.tscn`이 `GameSession`에 의존하지 않는다.
- **Godot 실행 파일을 못 찾으면 검증 수단이 없다.** 대비: 작업 0에서 멈추고 묻는다.
- **`DirAccess`로 `.tres`를 나열하는 방식은 내보낸 빌드에서 파일명이 달라진다.** 1단계는 에디터 실행만 대상이라 다루지 않는다. 보고서에 남긴다.

- 버전: v3 (1회차 디자인 APPROVE · 기술 REVISE(T1)를 받아 고쳤다 — 끝의 "검토 대응 기록". v2는 판 R의 답과 번호 바뀜 — "v2에서 바뀐 것")
- **실행 시점: 작업 0~4 전부를 R02(`docs/plans/R02-part-counter-feel.md`)의 마지막 커밋 뒤에 한다**(메인의 결정, 결정 545).
- 개발 단계: CLAUDE.md 9장의 단계 밖 갈래(규칙 갈래 R01~). 4단계 완료(2026-11-26), 설정 갈래 S01~S04 끝(2026-11-27), 5단계(사운드)는 사용자가 미뤘다(2026-11-27 "조금 미루고 다른거 먼저"). 이 갈래는 5단계로 넘어가지 않고, 5단계의 일(효과음·음악 만들기)을 하지 않는다.
- 이름: `R`(rules)은 설정 갈래 `S`와 같은 꼴이다. 단계 번호(0NN)를 쓰지 않는 까닭은 이 일이 9장의 어느 단계의 완료 기준에도 속하지 않아서다.
- 근거:

### 넘지 않는 선

- **게임 코드·씬·데이터·테스트를 고치지 않는다.** 이 계획이 바꾸는 것은 문서뿐이다(작업 4). 고칠 것은 판 R의 답에 따라 R03~(새 계획), BACKLOG(뒤로) 또는 "빼기"(설계 문서의 그 줄을 "넣지 않는다"로, 결정 537)로 보낸다.
- 그림·소리 생성 없음. 메인은 테스트·게임을 직접 실행하지 않는다(실행은 verifier, 판정은 사용자).
- 범위 밖: 5단계(사운드)와 6단계(콘텐츠: 새 의뢰·새 상대·스토리)의 일을 이 갈래에서 하지 않는다. 그쪽으로 갈 규칙은 "나중(6단계)"으로 적기만 한다.

## 목표와 범위

설계 문서에 있지만 없는 규칙(1절)과 지금 규칙의 약한 곳(2절)을 근거와 함께 한 판으로 보이고, 판 R의 답으로 "이번 갈래에 넣을 것 / 나중 / 빼기"를 정해 R03~R07의 차례를 확정한다(R02는 이미 있는 다른 계획).

**확인할 결과**:

1. 1절의 열네 줄과 2절의 열여섯 줄마다 근거(파일:줄 또는 결정 번호)가 있고, 추천이 하나다. 근거를 찾지 못한 칸은 "확인 못 함"이다.
2. 작업 2의 봇 통계로 T12(로렌초의 뛰어들기와 엉킴)를 쟀다. T1은 R02가 재고(2b절 X1), 지금 도구로 못 재는 T2는 "R06의 도구 줄"로 적혔다.
3. 판 R(R-1~R-4)의 답은 받았다(2026-11-27). 4절의 차례는 R02 → R03 → R04 → R05 → R06 → R07 하나다.
4. `docs/DECISIONS.md`(533~), `docs/BACKLOG.md`, `docs/HANDOFF.md`, `CLAUDE.md`(3·9·12장)가 그 답을 따른다. "빼기"로 정해진 규칙은 설계 문서에서 "넣지 않는다(R01)"로 표시된다(결정 537).

범위 밖(헷갈리기 쉬운 것): 규칙의 값 조정(제한 시간 90초, 빈틈 확률 등)은 R01에서 바꾸지 않는다. 보류 값(HANDOFF 3번)은 2절에서 "규칙에 걸린 것"만 짚고, 다시 열지는 사용자가 판 R의 글로 정한다.

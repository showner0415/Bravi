## 규칙

### 가. 별이 기본 보수에 비율을 더한다

| 별 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 손님 증감 (그대로) | −2 | −1 | 0 | +1 | +2 |
| 팁 덧붙임 (012) | −40% | −20% | 0 | +20% | +40% |
| **기본 보수 덧붙임 (새것)** | **−20%** | **−10%** | **0** | **+10%** | **+20%** |

- **비율을 절반으로 줄인다.** 까닭: 기본 보수는 팁보다 크다. 하루 셋의 기본 보수는 92~165이고 팁 최대는 51~90이다. 같은 ±40%면 돈의 폭이 012의 약 두 배가 된다(아래 "다른 비율" 표). ±20%이면 잘하는 손의 나흘 수입이 012와 거의 같다(정직·가장 큰 셋 845 → 831, 큰돈 100 983 → 981). 사용자 지시는 돈이 **어디에** 걸리는가였고 크기는 말하지 않았다. 그래서 012에서 승인된 돈의 크기를 지키고 자리만 옮긴다. 되돌리기 쉽다(`.tres` 한 줄). 사용자 결정 필요 1번에 올린다.
- 그날을 시작할 때의 별로 정한다(012와 같다). 하루 안에서는 바뀌지 않는다.
- **식**: 기본 보수 = 기본 보수 × (100 + 덧붙임)% × 보수에 쓰는 충족도 / 100. 반올림은 한 번이다(`round_div`, 0.5 올림). 덧붙임이 0이면 지금 식과 같은 정수다(아래 작업 1의 증명).
  - 순서: 충족도 비례와 덧붙임을 한 식에서 곱하고 마지막에 한 번 반올림한다.
  - 0점이면 보수에 쓰는 충족도가 0이라 기본 보수도 0이다.
  - 100 + 덧붙임은 0 아래로 자른다(음수 보수는 없다). 지금 표의 가장 낮은 합은 80%다.
- 팁의 식은 그대로다. `tip_bonus_percent`는 업그레이드(의자)만 움직인다.
- 경제 규칙에 새 필드 `base_bonus_percent`(기본 0)를 둔다. 평판이 그날의 사본에 더한다(012의 `settle_rules`가 팁에 하던 일을 기본 보수에 한다). 이 필드를 움직이는 업그레이드는 아직 없다.

**원칙 2(돈은 충족도로)와의 관계**: 돈은 여전히 충족도에 비례하고, 0점이면 0이다. 달라지는 것은 평판이 **어중간하게 해낸 판에도** 걸린다는 점이다. 012에서 팁에 걸었을 때는 충족도가 70을 넘어야 평판의 돈이 나왔다. 예를 들어 깃털(45 + 25), 충족도 60, 기준치 80이면 다음과 같다.

| 별 | 기본 보수 | 팁 | 합 |
|---|---|---|---|
| 별 3 | 34 | 4 | 38 |
| 별 1 (−20%) | 27 | 4 | 31 |
| 별 5 (+20%) | 41 | 4 | 45 |

평판은 "가게가 받는 값"을 바꾸고, 충족도는 "그 값 가운데 얼마를 받는가"를 정한다. 원칙 2와 부딪히지 않는다. 다만 낮은 별의 손이 어중간한 판에서도 덜 받는다(위험 참고).

### 나. "해내지 못했다"에도 날의 배율을 건다

- 맡는 값·이겼다·해냈다·흠 없이와 똑같이 `scaled(fail, 배율)`이다. 1일차 ×1은 지금 값이다. 크기는 1 아래로 내려가지 않으니 "최소한 −1"은 그대로 지켜진다.
- 배율 1.5의 값(맡는 값 / 해냈다 / 흠 없이 / 이겼다 / 못 해냈다):
  - 정직 0 / 5 / 3 / 2 / **−2**
  - 토마소 +3 / 5 / 3 / 2 / **−2**
  - 비토리오 −6 / 0 / 0 / 2 / **−2**
  - 가스파로 −9 / 0 / 0 / 0 / **−3**
- 배율 2는 다섯 항목 모두 1일차 값의 두 배다.
- 계획 011의 "깎이는 폭은 낮게"와의 관계: 1일차의 실패는 011의 크기(별 ⅛)이고, 3일차부터 010의 크기(별 ¼)가 된다. 오르는 값도 같은 배율로 커지므로, 날마다 "오르는 것 대 깎이는 것"의 비율은 011과 같다(정직한 일 흠 없이 6 대 1 → 12 대 2).

## 나흘 어림 (손 계산. 이 계획의 확인 기준)

- 1일차 손님 셋, 2~4일차 기준 5·목록 7, 결투 3이다. 80점 이상이면 보수를 다 받는다.

- 평판 (0점 줄 말고는 실패를 지나지 않아 012와 같다. 큰돈 100만 오는 순서로 다시 셌다)
  - 큰돈 100
    - 3일차: 44 −6 = 38, +10 → 44(잘림), −12 = 32
    - 4일차: 32 +12 → 44, −12 = 32, −6 = 26
  - 큰돈 85
    - 3일차: 34 −6 = 28, +6 = 34, −12 = 22
    - 4일차: 22 +8 = 30, −12 = 18, −6 = 12
  - 0점
    - 1일차: −1 ×3 → 17
    - 2일차(손님 5): 토마소 +3 −2 → 18, 오르솔라 −2 → 16, 가스파로 −9 −3 → 4(별 1)
    - 3일차(손님 3): 비토리오 −8 −2 → 0(잘림), 이네스 −2 → 0, 토마소 +4 −2 → 2
    - 4일차: 클라라 −2 → 0, 가스파로 −16 → 0, 에밀리오 −2 → 0

**다른 비율** (사용자 결정 필요 1번. 같은 여섯 플레이, 나흘 수입만)

| 기본 보수 덧붙임 | 정직 100·85 | 정직 · 가장 큰 셋 | 큰돈 100 | 큰돈 85 |
|---|---|---|---|---|
| ±20% (이 계획) | 723 | 831 | 981 | 948 |
| ±40% (012의 숫자 그대로) | 774 | 890 | 1042 | 977 |
| (012, 팁에 ±40%) | 733 | 845 | 983 | 950 |
| (011, 평판의 돈 없음) | 671 | 770 | 915 | 915 |

읽은 것:

- **돈과 업그레이드의 균형**: 잘하는 손의 나흘 수입은 012와 ±14 안이다. 정직(앞에서부터 셋)의 나흘 손익은 723 − 240 = 483이다(012 493, 011 431). 업그레이드 셋(180)과 임대료는 고치지 않는다.
- **궂은일**: 큰돈 100 − 정직·가장 큰 셋 = 150(012 138, 011 145). 궂은일의 기본 보수가 커서(가스파로 65, 비토리오 55), 기본 보수에 거는 비율은 큰돈 쪽에 조금 더 준다. 차이는 작다.
- **실패**: 0점 손은 2일차에 별 1(평판 4)이다. 012는 7이었지만 별은 같다. 2일차부터 정직한 실패가 −2다.

## 작업 목록

**공통 규칙** (계획 012와 같다)

- 메인 에이전트는 Godot을 어떤 방식으로도 실행하지 않는다. 확인은 파일 읽기, Grep, `git diff`, 손 계산뿐이다. 작업을 파일 하나씩 끊고, 작업마다 고친 함수를 다시 읽어 아래 확인 방법을 따른다.
- GDScript는 지금 파일들의 문법만 쓴다. 이미 있는 함수의 인자는 늘리지 않는다(이 계획은 시그니처를 바꾸지 않는다). 새 필드의 기본값은 "지금과 같은 동작"이다.
- 대조나 손 계산이 어긋나면 값을 맞추지 말고 멈춰서 보고한다.
- **스크립트를 하나 고칠 때마다 확인할 것**:
  1. 들여쓰기: 고친 `.gd`에서 `^ +\S`를 Grep해 0건이다(`scripts/`는 탭만 쓴다).
  2. 같은 함수 안의 이름 겹침. 새 지역 변수는 아래 이름을 피한다. 멤버 `rules`와 같은 이름의 지역 변수는 `settle_rules()` 안에서 쓰지 않는다.
     - `settlement.gd`의 `_build`: `line`, `rules`, `ledger`, `note`, `proceed`, `missed`, `threshold`, `note_text`, `tip_text`
     - `counter.gd`의 `_build`: `reputation`, `base`, `guests`, `accept`, `hint`, `note`, `proceed`, `decline`, `quit`, `first_counter`, `guest_text`
     - `closing.gd`의 `reputation_ledger_text`: `rules`, `before`, `after`, `first`, `to_next`, `second`, `base`, `stars_before`, `stars_after`, `next_star`, `guest_gain`, `changes`
     - `day_state.gd`의 `finish_duel`: `commission`, `economy`, `result`, `won`, `items`
     - `day_state.gd`의 `payout`: `paid`, `base`, `tip`, `tip_score`, `tip_floor`
  3. Variant 추론: 고친 파일에서 `:= .*\.get\(`을 Grep해 전부 `int(...)`나 `String(...)`으로 감쌌다(`reputation_pay_percent`를 읽는 곳).
  4. 서식 문자열: `%` 연산자를 거치는 글의 퍼센트 글자는 `%%`, 거치지 않는 글은 `%` 하나다. 줄마다 자리 수와 인자 수를 센다. `%+d%%`가 들어가는 곳은 `reputation_text`, GuestNote 상수 둘, 정산의 기본 보수 줄, 폐점의 두 줄이다.
  5. `@warning_ignore("integer_division")`는 나눗셈이 든 문장 바로 윗줄에 둔다.

### 작업 1. 경제 규칙과 돈의 식

- 대상: `scripts/economy/economy_rules.gd`, `scripts/economy/day_state.gd`(`payout`, 새 `boosted_base_max`, `settle`)
- 무엇:
  - `EconomyRules`: `@export var base_bonus_percent := 0`. 주석은 "기본 보수에 덧붙는 비율(%). 0이면 덧붙임이 없을 때와 같은 값이다. 지금은 평판(별)이 그날의 사본에만 더한다"이다. `data/economy_rules.tres`는 고치지 않는다(기본 0).
  - `payout`: `var base := round_div(base_reward * maxi(100 + p_rules.base_bonus_percent, 0), paid, 10000)`. 함수 머리 주석에 한 줄을 더한다.
  - `static func boosted_base_max(base_reward: int, p_rules: EconomyRules) -> int`: `round_div(base_reward, maxi(100 + p_rules.base_bonus_percent, 0), 100)`.
  - `settle`의 `"base_max"`: `boosted_base_max(commission.base_reward, p_rules)`.
- 완료 확인:
  - **덧붙임 0이면 같은 정수인지 손으로 증명한다**: `round_div(a×100, b, 10000)` = (a×100×b×2 + 10000) / 20000 = (a×b×2 + 100) / 200 = `round_div(a, b, 100)`. 정수 나눗셈에서 분자와 분모를 100으로 나눈 것과 같은 몫이다. `boosted_base_max(a, 0)` = (a×100×2 + 100) / 200 = a. 그래서 테스트의 모든 `payout` 호출과 `tests/day_tests.gd` 247줄(`base_max == base_reward`)이 그대로다.
  - 손 대입: `payout(100, 45, 25, 덧붙임 10, 기준치 80)` → 기본 50, 팁 25. `payout(60, 45, 25, 덧붙임 −20, 기준치 80)` → 보수에 쓰는 충족도 75, 기본 27, 팁 4. 덧붙임 0이면 기본 34, 팁 4. `payout(0, …)` → 0, 0.

- **실행으로 확인하지 못한다. 스크립트 일곱 개를 고친다**: `economy_rules`, `day_state`, `reputation_rules`, `day_ui`, `counter`, `settlement`, `closing`. 012의 스크립트 여섯 개도 아직 아무도 켜 보지 않았다. 대비는 공통 규칙의 다섯 가지 확인과 작업 6의 옛 이름 0건이다. 처음 켤 때 오류가 나면 012와 013의 변경 파일이 첫 의심 대상이다.
- **이름을 바꾸다 놓치면** 타입이 붙은 호출이 스크립트를 못 읽게 한다. 대비: 작업 6의 Grep을 `scripts/`·`tests/`·`data/` 세 곳에서 한다.
- **낮은 별의 손이 어중간한 판에서도 덜 받는다**(012는 70점 초과에서만). 별 1에서 −20%다. 지금의 어림에서는 0점 손만 별 1~2라 돈의 차이가 나지 않는다. 실패와 성공이 섞인 손에게는 내리막이 012보다 가파르다. 대비: 사용자 결정 필요 2번.
- **3일차부터 실패가 010의 크기(별 ¼)다.** 사용자의 지시다. 오르는 값도 같이 커져 비율은 011과 같다.

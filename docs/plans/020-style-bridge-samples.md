## 참고 자료의 자리와 선

- **자리**: `docs/style/reference/`. 메인이 처음 말한 `assets/art/reference/`가 아니다. 까닭: `assets/`는 4단계부터 게임 애셋(`MANIFEST.md`에 적는 것)만 두는 곳이고, 3단계의 견본·참고는 한 폴더(`docs/style/`)에 모아 `.gdignore` 하나로 Godot이 가져오지 않게 한다(Godot은 프로젝트 안의 PNG·JPG·SVG를 가져와 옆에 `.import`를 만든다).
- **저장소**: 참고 스크린샷(상용 게임의 이미지)은 **로컬에만 둔다**(`.gitignore`). 원격 저장소가 비공개여도 올리지 않는다. 저장소에는 글로 된 색인 `docs/style/REFERENCES.md`(파일 이름, 사용자 메모, 말로 적은 성질)와 폴더 안내 `docs/style/reference/README.md`만 올린다. 다른 컴퓨터에서 이어 받으면 사용자가 그림을 따로 옮긴다(`HANDOFF.md`에 적는다). 견본(우리 그림)은 올린다.
- **따라 그리지 않는 선**(결정 179. CLAUDE.md 7장에 둔다):
  1. 참고 이미지를 따라 그리거나, 겹쳐 놓고 그리거나, 잘라 쓰지 않는다. 견본은 우리 게임의 장면(바르톨로, 카운터의 의뢰인)을 새로 그린 것이다.
  2. 두 게임의 인물·의상·로고·UI 틀·아이콘·글꼴을 옮기지 않는다. 가져오는 것은 말로 적을 수 있는 성질뿐이다(선의 굵기와 색, 머리와 몸의 비, 칠의 단계 수, 질감의 종류, 색의 채도·명도 범위).
  3. 이미지 생성에 참고 스크린샷을 이미지 입력(이미지 프롬프트, 스타일 참조, img2img)으로 넣지 않는다. 프롬프트에 두 게임·제작사·작가의 이름을 쓰지 않는다.
  4. 참고 스크린샷을 저장소 밖(Artifact 등)에 올리지 않는다.

## 목표와 범위

**확인할 결과** (메인은 파일 읽기·Grep·Glob·git·손 계산과 구운 PNG를 Read로 보기로 확인한다. 고르는 것은 사용자다)

1. 사용자가 브라우저에서 다리 견본 셋(A·B·C)을 **같은 장면, 같은 자리**로 나란히 보고, 인물의 선·칠·그림자 가운데 무엇을 가져갈지 고를 수 있다. 결투의 무대도 **짙은 무대와 밝은 양피지 무대를 같은 구도로 바꿔 보며** 고를 수 있다(작업 5의 물음. v3, D1).
2. 셋 모두에서 결투의 예비 동작이 읽히는지 견본 위에서 볼 수 있다: 상태 넷(대기·예비 동작·빈틈·무너짐)과 멀리의 방심이 지금 코드의 색·포즈·글자(두 줄 포함)·고리·조준 그대로 얹혀 있고(근거의 "코드의 사실"), 색을 빼도(흑백) 포즈로 갈린다. 두 무대의 대비가 숫자로 적혀 있다.
3. 견본의 상대가 결정 12의 이름·계층·관절 자리대로 나뉘고, 파츠마다 칠과 선이 따로다(상태 색은 칠에만).
4. 참고 스크린샷은 로컬에만 있고(git이 무시한다), `docs/style/` 아래는 Godot이 가져오지 않는다. 저장소에는 글 색인만 있다.
5. 따라 그리지 않는 선이 CLAUDE.md 7장과 `docs/DECISIONS.md`에 있다.

**범위 밖**: 기준 이미지의 선택과 `docs/STYLE_BIBLE.md`(021·022), 글꼴·확정 팔레트·완성 파츠·UI 요소(021), 이미지 생성, `assets/`와 `MANIFEST.md`(022·4단계), 게임의 `scripts/`·`scenes/`·`data/`·`tests/`·`project.godot`. 감정 상태 셋(침착·흥분·겁먹음)은 게임에 없으므로 표정은 상태(대기·예비 동작·무너짐)로만 그려 본다.

## 작업 목록

**공통 규칙**

- 메인은 Godot을 어떤 방식으로도 실행하지 않는다. Edge headless로 HTML을 PNG로 굽는 것은 Godot이 아니므로 한다(작업 4).
- 고치지 않는다: `scripts/`, `scenes/`, `data/`, `tests/`, `project.godot`, `docs/BACKLOG.md`의 기존 항목, 사용자의 파일. 만드는 것은 `docs/style/` 아래의 파일, `.gitignore`의 세 줄, 작업 6의 기록(BACKLOG의 새 항목 하나 포함)뿐이다. `assets/`는 만들지 않는다.
- 견본은 새로 그린 것이다: 견본 파일에 참고 이미지를 넣거나 가리키지 않는다.

## 위험

1. **메인이 보지 않고 그린다.** SVG를 글로 쓰므로 모양이 어긋나도 모른다. 대비: 작업 4의 굽기(한 장씩 끝을 기다린다)와 Read, 표 아홉 칸, `--dump-dom`의 수. 굽기가 안 되면 사용자의 눈뿐이고 보고서에 그렇게 적는다.
2. **SVG의 질감은 흉내까지다.** 사용자가 "느낌"을 고르기 어려울 수 있다. 대비: 페이지 머리에 "방향을 고르는 견본"이라 적고, 물음을 축(선·칠·그림자)으로 나눴다. 완성 품질은 021.
3. **견본이 크다(16 섹션, 상대 30번, 구울 그림 22장).** 대비: 상대 하나를 한 번 정의해(스크립트 함수나 공통 조각) class와 변수로 바꾼다. 결투를 먼저, 카운터는 나중. 카운터를 못 그리면 결투만 보인다(작업 3).
4. **상용 이미지가 밖으로 나간다.** 대비: `.gitignore`와 `git check-ignore`, `git log -- docs/style/reference`가 빈 것을 확인. 견본에 참고 이미지를 넣지 않는다(Grep). Artifact에는 견본만.
5. **무대의 두 길 모두에 대가가 있다.** 짙은 무대는 포션 크래프트의 밝은 양피지 느낌과 멀고, 밝은 무대는 예비 동작으로 물든 칠이 바탕에 묻힌다(작업 3의 대비 표). 대비: 두 무대를 같은 구도로 그리고 숫자와 함께 물음 2로 사용자가 고른다(결정 182). 밝은 무대를 고르면 4단계에서 신호 표시(테두리, 칠)를 손볼 일이 생긴다.
6. **견본의 꼴이 4단계의 제작 길과 맞지 않을 수 있다.** Godot의 SVG 가져오기가 SVG 필터(`feTurbulence` 등)를 다 그리지 못할 수 있다(확인 필요). 생성 그림(GPT)은 정면 구도와 파츠 분리를 지키기 어렵다. 대비: 021에서 약관을 확인한 뒤 GPT 생성과 SVG를 상대 한 명으로 시험해 만드는 길을 정한다. 필터를 쓴 질감은 PNG로 구워 가져오는 길이 있다.
7. **상태 색을 칠에만 입히는 것은 지금 코드와 다르다.** 지금은 `Polygon2D` 하나의 색을 통째로 바꾼다. 일러스트로 바꿀 때 `modulate`(곱하기)로는 같은 섞임이 나오지 않는다. 대비: 이 계획은 견본으로 보이기만 하고 코드를 바꾸지 않는다. 4단계에서 칠·선 두 노드나 셰이더로 정한다(보고서 3번에 적는다).
8. **Edge의 모습과 사용자 브라우저의 모습이 다를 수 있다**(글꼴, 필터). 대비: 글꼴은 자리만 잡았다고 적는다. 사용자가 본 모습이 기준이다.
9. **지금 게임에도 겹침이 있다**(v3에서 드러났다). 두 줄 상태 글자가 교전의 깃털 끝, 밀착의 엉킴 경고와 겹친다. 대비: 견본은 겹치지 않는 꼴로 그리고, 게임 쪽은 BACKLOG 020-1로 남긴다(작업 6). 020에서 코드는 고치지 않는다.
10. **굽기가 사용자의 Edge를 건드린다.** 대비: 따로 된 프로필, 한 장씩 차례로, 끄는 것은 띄운 PID의 나무와 우리 프로필의 프로세스뿐(이름으로 끄지 않는다. 작업 4).

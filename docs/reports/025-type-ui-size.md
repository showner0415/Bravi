확인 못 한 것:

- **Godot에서의 글자 모습**(힌팅, 줄 높이, 테두리의 꼴). 상태 글자의 상자와 가장 작은 글자는 Edge에서 잰 값이다.
- 사용자의 브라우저에서 로컬 글꼴이 읽히는지(판정은 구운 그림으로 했다).
- 버튼의 올림·누름이 실제로 움직일 때의 모습, 1920×1080보다 큰 창.
- 획의 진하기(V·Hz)는 크기마다 들쭉날쭉해 글꼴을 가르는 힘이 약했다. 값은 적었지만 판정은 눈으로 했다.
- 늘린 무대 그림의 윤곽은 읽을 줄을 찾지 못해 눈으로만 보았다.
- **playtester에게 맡길 확인**: 새로 생긴 것이 없다(게임이 바뀌지 않았고 저장소에 그림·글꼴이 더해지지 않았다). 024 보고서의 둘이 그대로 남아 있다.

## 4. 사용자가 결정해야 할 것

1. **024·025의 커밋**: 둘 다 커밋 전이다(024의 기준 이미지 약 9.8MB 포함. 글꼴은 올라가지 않는다).
2. **해상도의 기준**(4단계의 일을 정한다): 1920×1080 창에서 늘어나지 않게 하려면 파츠 시트를 더 크게(또는 두 장으로 나눠) 그리고 무대를 1920 폭 이상으로 만들어야 한다. 2560×1440까지 볼지도 그때 정한다.
3. **그린 질감**(양피지, 장식 테두리): 지금은 견본의 필터로 흉내 낸 종이 결뿐이다. 4단계에서 그림으로 만들지.
4. **송명의 글자 수**: 2,350자뿐이다. 지금 글은 다 있지만 6단계에서 글이 늘면 빠지는 글자가 생길 수 있다. 그때 다시 세고, 빠지면 그 글자만 다른 글꼴로 받치거나 제목 글꼴을 다시 고른다.
5. **글자 크기를 아홉 단계로 옮기기**와 **HUD의 자리 손보기**(패널이 서로 겹치는 곳, 방심 막대의 자리, 찬 막대 위의 충족도 라벨): 4단계에서 할지.
6. 보류 중인 것은 그대로다: 2단계의 값과 결정(`docs/HANDOFF.md` 3번), `docs/BACKLOG.md`, `docs/plans/013-playtester.md`의 번호 겹침.

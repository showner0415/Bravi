## 2. 직접 실행해서 확인한 것 / 확인 못 한 것

**확인한 것**(playtester, Godot 4.7.2. 두 번째 확인)

- 테스트 `ALL PASS 82/82`, 스모크 OK, 상대 찍기 57장·UI 찍기 15장 OK. 가져오기의 오류·누수는 0이다.
- 게임 창:
  - 네 패턴 모두 번호 고리와 "(k/n)" 글자가 뜬다.
  - 다 막으면 빈틈이 열리고, 큰 공격이면 "크게 열림!"이 뜬다.
  - 하나를 놓치면 그 한 번만 맞고 패턴이 끝난다.
  - 이어 베기는 박자마다 패리할 수 있다.
  - 휩쓸기는 쥔 채 끌면 다 막히고, 떼었다 누르면 그 점에서 맞는다. 새로 눌러도 패리가 아니다.
- 자유 결투: 바르톨로 60.5초, 브루노 51.3초. 패턴은 판마다 4번쯤 단발과 섞여 나온다. R과 Esc가 듣는다.
- 회귀: 연습의 의뢰 카드와 하루 1일차 결투에는 패턴이 0번이고 전과 같다.
- 사용자가 직접 해 보고 "지금은 이대로도 좋은거 같아"라고 했다.

**확인 못 한 것**

- 판 길이(P3)의 답은 받지 못했다. 제한 90초 그대로 둔다.
- "누른 채 옮기기"와 "박자마다 새로 누르기" 가운데 어느 쪽이 재미있었는지, 이어 베기와 휩쓸기가 다른 손으로 느껴졌는지는 답을 받지 못했다.
- playtester의 입력은 0.13~0.15초 간격으로 장을 찍는 스크립트라, 패리 창의 정확한 앞뒤와 장 사이의 빠른 움직임은 보지 못했다.

## 3. 설계 문서와 다르게 구현한 부분과 이유

- **`chain`의 타입**: `Array[Resource]`다. 계획은 `Array[AttackData]`였는데, 자기 클래스를 원소 타입으로 쓰면 끝날 때 누수 오류가 나고 모든 러너가 가져오기 단계에서 멈췄다(첫 확인의 E1).
- **버틴 첫 타격은 패턴을 끝낸다**: 계획의 글대로 짜면 버티기의 대가가 사라졌다. 기술 검토의 제안을 따랐고, T81이 패턴의 뿌리를 올려 막기 공격으로 두는 것을 막는다.
- **T22를 고쳤다**: 계획은 기존 테스트의 기대 값을 고치지 않는다고 했다. 그런데 T22가 연습 화면의 모든 버튼을 세고 있었다. 새 버튼 여섯 때문에 실패해 카드의 시작 버튼만 세게 했다.
- **메인의 실수**: 테스트 파일의 한 줄에 줄바꿈 대신 글자 `\n`이 들어갔다(첫 확인의 E2). 고쳤다.
- **판정 판을 선택 창으로 묻지 못했다**: 사용자가 먼저 글로 답했다. P1·P2는 "쓴다"로 읽었다.
- **메인이 게임을 한 번 직접 켰다**: 사용자가 "니가 직접 켜줘"라고 했다.

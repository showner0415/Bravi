계획 011을 끝까지 실행했습니다. 바꾼 것은 데이터의 숫자뿐입니다. 평판이 오르는 값은 커졌고, 못 해냈을 때 깎이는 값은 작아졌습니다. 테스트는 사용자 규칙에 따라 돌리지 않았습니다. 확인은 값 대조, `git diff`, 손 계산으로 했습니다.

## 1. 한 일

−1보다 작게 깎으려면 정수로는 0밖에 남지 않습니다. 그래서 **평판의 눈금을 두 배로 늘렸습니다.** 폭은 "별 하나에 견준 크기"로 비교합니다.

**평판 규칙** (`data/reputation_rules.tres`)

| 값 | 전 | 새 값 |
|---|---|---|
| 시작 | 9 | 20 (별 3의 가운데) |
| 범위 | 0~20 | 0~44 |
| 별의 문턱 | 4·8·12·16 | 8·16·24·36 |
| 흠 없이의 덤 | +1 | +2 |
| 손님 증감 | −2~+2 | 그대로 |

**의뢰 일곱** (맡으면 / 해내면 / 못 해내면)

| 의뢰인 | 전 | 새 값 |
|---|---|---|
| 에밀리오·클라라·이네스·오르솔라 | 0 / +1 / −1 | 0 / +3 / −1 |
| 토마소 (가난한 손님) | +1 / +1 / −1 | +2 / +3 / −1 |
| 비토리오 (대금업자) | −2 / 0 / −1 | −4 / 0 / −1 |
| 가스파로 (노름꾼) | −3 / 0 / −2 | −6 / 0 / −2 |

**별 하나에 견준 크기**

| 무엇 | 전 | 새 값 |
|---|---|---|
| 정직한 일을 흠 없이 | ½ | ⅝ ↑ |
| 정직한 일을 해냄(71~99점) | ¼ | ⅜ ↑ |
| 토마소를 흠 없이 | ¾ | ⅞ ↑ |
| 못 해냄 | ¼ | ⅛ ↓ |
| 궂은일을 못 해냈을 때 더 깎이는 값 | 비토리오 ¼, 가스파로 ½ | 비토리오 ⅛, 가스파로 ¼ ↓ |
| 궂은일을 맡는 값 | 비토리오 ½, 가스파로 ¾ | 그대로 |

- 별 4만 폭이 12점입니다. 8점으로 두면 정직한 손님 셋을 흠 없이 해낸 1일차에 별 다섯이 됩니다.
- 토마소는 0점이어도 평판이 +1입니다. 돈은 0이고 흠 없이 해내면 +7이라, 일부러 질 이득은 없습니다.
- 평판의 식, 손님 수의 식, 화면, 돈은 그대로입니다.

## 2. 확인한 것 / 못 한 것

**확인한 것** (실행 없이)

- **값 대조**: 바꾼 파일을 다시 읽어 표와 한 칸씩 맞춰 봤습니다. `git diff`에서 바뀐 줄은 규칙 파일 4줄, 의뢰 파일마다 1줄이고, 숫자 말고 바뀐 글자는 없습니다.
- **구조 조건**: 문턱이 오름차순이고, 0 ≤ 시작 20 ≤ 44이며, 맨 위 문턱 36 ≤ 44입니다. T52가 로드한 값에서 보는 조건과 같습니다.
- **손 계산**: 디스크의 값과 `ReputationRules`의 식으로 나흘 어림을 다시 계산했습니다. 칸마다 계획과 같았습니다.

  | 플레이 | 1일차 | 2일차 | 3일차 | 4일차 |
  |---|---|---|---|---|
  | 정직한 손님 셋을 전부 100점 | 3명 · 185 → 35(별 4) | 6명 · 143 → 44(별 5) | 7명 · 158 → 44 | 7명 · 185 → 44 |
  | 보수가 큰 셋을 전부 100점 | 3명 · 185 → 35(별 4) | 6명 · 240 → 39(별 5) | 7명 · 245 → 34(별 4) | 6명 · 245 → 29(별 4) |
  | 보수가 큰 셋을 전부 85점 | 3명 · 185 → 29(별 4) | 6명 · 240 → 29(별 4) | 6명 · 245 → 22(별 3) | 5명 · 245 → 15(별 2) |
  | 앞에서부터 셋을 전부 0점 | 3명 · 0 → 17(별 3) | 5명 · 0 → 9(별 2) | 4명 · 0 → 4(별 1) | 3명 · 0 → 0(별 1) |

  - 잘하는 손은 전처럼 이틀째에 별 다섯입니다.
  - 내려가는 쪽은 느려졌습니다. 4일차 뒤의 별은 큰돈 100점이 별 3 → 4, 큰돈 85점이 별 1 → 2입니다.
  - 나흘 수입은 그대로입니다(671 / 915 / 915 / 0).
  - 손님 수는 큰돈 85점이 3·6·5·4에서 3·6·6·5로, 0점이 3·4·3·3에서 3·5·4·3으로 늘었습니다.
- **테스트 파일**: `tests/`를 Grep해 봤습니다. 평판 숫자를 기대하는 곳은 테스트가 직접 만든 규칙(`_rep_rules()`)뿐입니다. 로드한 `.tres`에서는 구조만 보고, 나머지는 INFO 줄입니다. 그래서 고치지 않았습니다.

**확인 못 한 것** (사용자 규칙: 테스트는 사용자의 에이전트가 준비될 때까지 돌리지 않습니다)

- 테스트가 `ALL PASS 55/55` 그대로인지, 스모크가 `RESULT: OK`·씬 24개인지.
  - 코드를 읽고 기대하는 값: 스모크 1일차 뒤 평판 23·별 3, 2일차 손님 5.

## 4. 결정해 주실 것

1. **"깎이는 폭"에 궂은일을 맡는 값(비토리오, 가스파로)도 들어가나요?** 지금은 들어가지 않는다고 보고, 별 하나에 견준 크기를 그대로 뒀습니다(비토리오 −4, 가스파로 −6).
   - 지금(그대로): 보수가 큰 셋만 흠 없이 해내면 4일차 뒤 별 4로 내려갑니다.
   - 같이 줄이면(−2, −3): 같은 플레이로 나흘 내내 별 5에 머뭅니다. 궂은일을 고르는 대가가 거의 사라집니다.
   - 바꾸려면 의뢰 두 파일의 숫자를 하나씩 고치면 됩니다.
2. **오르는 속도**: 정직하게 잘하면 2일차에 별 다섯이 됩니다. 더 빠르게 하려면 별 4의 문턱 36을 32로 내리고, 더 느리게 하려면 40 이상으로 올립니다.
3. **실패의 무게**: 못 해내면 −1(별 ⅛)입니다. 0으로 하면 실력으로는 평판이 깎이지 않고, 정산의 "해내지 못했다" 줄이 사라집니다.
4. 계획 010 보고서 4장의 열린 것에는 아직 답이 없습니다. 평판이 무엇을 바꾸는가, 긴 손님 줄이 상인가, 임시 결정 넷입니다.

## 플레이 체크리스트 O (계획 011의 숫자로 고친 것)

실행: `powershell -ExecutionPolicy Bypass -File play.ps1`. 나흘을 한 번에 이어서 봅니다.

1. **읽혔는가**: 평판이 왜 오르고 내렸는지 정산에서 알 수 있었는가. 폐점의 "내일의 손님"을 봤는가.
2. **고르게 됐는가**: 평판 때문에 맡거나 돌려보낸 손님이 있었는가(토마소, 가스파로, 비토리오). 카운터의 "소문" 줄을 봤는가.
3. **대가**: 손님 줄이 늘거나 준 것을 느꼈는가. 늘어난 줄이 상으로 느껴졌는가.
4. **흠 없이**: 80점을 넘긴 뒤에도 100점을 노리게 됐는가.
5. **속도**: 오르는 쪽이 시원하게 느껴졌는가. 깎이는 쪽이 너무 가벼워 평판이 숫자로만 남았는가.

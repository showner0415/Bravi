## 3. 계획과 다르게 한 것

- **생성 무대를 셋 만들었다.** 계획은 승인 B에서 고른 하나였는데, 사용자가 "배경을 여러개 만들 생각이고 뒷골목, 안뜰, 광장 3개 다 만들어줘"라고 했다. 장·호출은 상한 8 안의 7이다. 그래서 견본의 생성 무대 섹션도 셋이고, 섹션은 26, `data-part`는 29씩이다(계획은 24와 27).
- **G1의 H2를 승인 B에서 잘못 알렸다.** 줄인 그림만 보고 "팔과 몸통 사이에 틈이 없다"고 했는데, 화소로 재니 10~18px의 틈이 있었다. 결과는 통과이고 `GENERATION.md`에 바로잡아 적었다. 다시 뽑지 않기로 한 답에는 영향이 없다.
- **프롬프트 확인의 Grep 하나를 좁혔다.** 계획의 G1 전문에 그림 도구의 인자 이름인 "referenced image"가 들어 있어, Grep `reference`는 일곱 파일 모두에 걸린다. 참고 스크린샷이 없다는 확인은 `reference/|screenshot` 0건으로 했다.
- **끄기를 더했다.** 계획의 `-c` 끄기에 더해 `--disable plugins/apps/computer_use/browser_use/browser_use_external`를 썼다(계획이 작업 4에서 보라고 한 "그 호출만의 끄기 기능"이다). `codex mcp list`로 플러그인이 가져온 MCP 둘이 사라지는 것을 봤다.
- 세션 기록의 Grep은 2회차 기술 검토의 제안대로 도구 정의의 `"name"`과 호출 항목 줄로만 셌다.
- 상태 색을 래스터의 밝기 문턱으로 칠에만 입혔다(지금 게임은 파츠 전체의 색을 바꾼다). 4단계 셰이더 후보다.
- 그림 생성은 사용자 지시대로 `gpt-6.2-sol`·`high`로 돌렸다(사용자 설정의 모델 `gpt-6.2-astra`와 다르다. 설정 파일은 그대로다).
- 생성 그림의 머리·모자·팔을 사용자가 고른 비례(머리 104, 팔 105)에 맞춰 줄였다. 원래 비는 `GENERATION.md`와 견본의 팔레트에 있다.
- 안뜰 대문의 징을 양피지색에서 짙은 색으로 바꿨다(가운데 띠 L ≤ 0.20).
- 견본에서 내 손을 안내 띠 위에 그렸다(020과 같다).

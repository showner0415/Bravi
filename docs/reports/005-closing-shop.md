# 계획 005 보고서: 폐점의 가게

- 날짜: 2026-11-19
- 계획: `docs/plans/005-closing-shop.md` (v2)
- 브랜치: `stage2-day-loop-v2` (커밋하지 않았다. 작업 트리에만 있다)

계획 005(폐점의 가게)를 끝까지 실행했습니다. 가게를 닫을 때 번 돈으로 업그레이드 셋을 살 수 있고, 산 것은 다음 날의 결투와 정산에 적용됩니다.

## 1. 한 일

- **업그레이드 데이터**: 업그레이드 하나는 "어느 규칙의 어느 숫자에 얼마를 더하는가"를 적은 Resource입니다. `.tres`만 더하면 새 업그레이드가 가게에 나옵니다 (`scripts/economy/upgrade_data.gd`, `upgrade_catalog.gd`, `data/upgrades/` 셋, `data/upgrade_catalog.tres`).

  | 이름 | 값 | 효과 |
  |---|---|---|
  | 상비약 상자 | 30 | 치료비 −10 (20 → 10) |
  | 응접실 의자 | 60 | 팁 +30% |
  | 누빈 조끼 | 90 | 내 자세 +1 (3 → 4). 져 줘야 하는 의뢰에서는 한 번 더 맞아야 한다 |

- **구매 규칙**: 폐점에서만 사고, 소지금이 모자라면 못 사고, 같은 것은 한 번만 삽니다. 효과는 다음 날부터 나고, 처음 화면으로 나가면 사라집니다 (`scripts/economy/day_state.gd`, `economy_rules.gd`).
- **폐점 화면**: 왼쪽은 장부, 오른쪽은 가게입니다. 살 것이 있는 날에는 Space로 넘어가지 않고, "다음 날을 연다" 위에 안내 한 줄이 뜹니다 (`scripts/economy/closing.gd`).
- **결투와 정산**: 하루 중의 결투는 산 것이 적용된 규칙으로 돌고, 연습은 기본 규칙 그대로입니다 (`scripts/duel/duel_scene.gd`, `scripts/economy/settlement.gd`, `scripts/game_session.gd`).
- **도구**: 테스트·스모크 스크립트가 이 PC의 Godot를 스스로 찾습니다. 게임은 `play.ps1`로 켭니다(클래스 캐시를 갱신한 뒤 켜므로 브랜치를 바꿔도 죽은 처음 화면이 뜨지 않습니다) (`tests/godot_path.ps1`, `tests/run_tests.ps1`, `tests/run_smoke.ps1`, `play.ps1`).
- **테스트**: T34~T36을 더했고, 스모크가 "사고 → 다음 날 적용"까지 19개 씬을 지납니다 (`tests/day_tests.gd`, `tests/day_smoke.gd`, `tests/duel_bots.gd`).
- **기록**: `docs/DECISIONS.md`에 위임 사실과 결정 42~55, 실행 중에 정한 것을 적었습니다. `CLAUDE.md`는 아래 네 곳만 고쳤습니다.

`CLAUDE.md`에서 고친 줄:

- 5장 끝에 더함: "지금 만든 범위(계획 005까지): 처음 화면(가게를 연다 / 연습), 고정 의뢰 3건을 차례로 맡는 하루, 하루 중의 결투는 한 번뿐, 충족도에 따른 기본 보수와 팁, 폐점의 임대료·치료비와 업그레이드 구매(효과는 다음 날부터). 아직 없는 것: 거절, 협상, 평판, 칼 수리비, 부상에 따른 의뢰 수 감소, 날마다 다른 의뢰, 저장."
- 8장: `data/` 줄에 `days/`, `upgrades/`와 `data/` 바로 아래의 `.tres` 셋을 더하고, `play.ps1` 줄을 더함.
- 9장 "현재 위치" 줄 끝에 더함: "계획 005(폐점의 가게)까지 실행했다."
- 12장 승리 보상 줄 끝에 더함: "임시(2026-11-19 위임으로 정함): 2단계에서는 만들지 않는다. 평판과 한 점수로 할지 따로 둘지는 평판을 만드는 계획에서 정한다(기운 안: 한 점수)"

## 2. 확인한 것 / 못 한 것

**확인한 것**

- 테스트: `RESULT: OK (ALL PASS 37/37, error lines 0, warning lines 0)`. 기존 T0~T33은 기대값을 고치지 않고 통과했습니다(보수 표 T29, 장부 T31 포함).
- 스모크: 세 번 연속 `RESULT: OK (DAY SMOKE OK, error lines 0, warning lines 0)`. 축소 없이 돌았습니다. 세 번 모두 같은 출력입니다.

  ```
  DAY SMOKE 장부: 수입 45, 임대료 60, 부상 2회, 치료비 40, 손익 -55, 소지금 -55
  DAY SMOKE 지갑 채움: 180
  DAY SMOKE 구매: 3개를 전부 삼, 소지금 0
  DAY SMOKE 2일차 결투: 내 자세 4 (기본 3)
  DAY SMOKE 2일차 정산: 치료비 10 (기본 20)
  DAY SMOKE OK (씬 19개를 순서대로 지남)
  ```

- 도구: 인자 없이 돌린 테스트와 스모크가 이 PC의 Godot를 찾았습니다. 없는 경로를 주면 `RESULT: FAIL (Godot not found: C:\no\such.exe …)`로 끝납니다. `play.ps1 --headless --quit-after 300`은 오류 줄 없이 종료 코드 0이었습니다.
- 씬 직접 실행: 폐점 씬과 결투 씬을 각각 헤드리스로 띄워 오류 줄이 0이었습니다.
- 스크린샷(창을 띄운 스모크로 18장 저장, 그중 아래를 열어 봄):
  - 폐점 "사기 전"(소지금 −55): 버튼 셋이 회색으로 눌리지 않고, "다음 날을 연다"에 포커스 테두리가 있습니다.
  - 폐점 "하나 산 뒤": 산 것은 금색 "상비약 상자 — 샀다", 나머지 둘은 흰 글씨로 살 수 있게 보입니다. 안내 한 줄이 버튼 위에 뜨고 "다음 날을 연다"에는 포커스가 없습니다.
  - 폐점 "다 산 뒤": 셋 다 금색 "샀다", 소지금 0, 포커스가 "다음 날을 연다"로 돌아옵니다.
  - 장부와 가게가 겹치거나 잘리지 않고, 조끼의 긴 설명 글이 한 줄에 들어갑니다.
  - 1일차 첫 정산(봇이 첫 피를 해냄): 충족도 100, 기본 보수 30/30, 팁 15/15, 받은 돈 45. 004에서 못 본 "돈이 들어온 정산 화면"입니다.
  - 2일차 결투: HUD의 내 자세가 4/4, 칸 넷입니다.
  - 2일차 정산: 팁의 최대가 15에서 20으로, 치료비가 10으로 보입니다.

**확인 못 한 것**

- 벌어서 사는 실제 경로는 스모크가 지나지 않습니다. 스모크는 지갑에 180을 직접 넣었고, 벌어서 사는 계산은 T35가 숫자로만 검사합니다.
- 돈이 들어온 폐점 화면(손익이 양수인 날)은 스크린샷에 없습니다. 스모크의 둘째·셋째 판은 입력 없이 진 판입니다.
- `play.ps1`을 인자 없이 돌려 창이 뜨는 것은 보지 않았습니다(헤드리스 인자로만 지났습니다).
- 마우스로 실제 클릭해 사는 것, Space 연타로 폐점을 지나치지 않는 것은 사람 손으로만 확인됩니다. 포커스 규칙은 T36이 코드로 확인했습니다.
- 돈이 신경 쓰이게 됐는지, 값이 맞는지는 아래 체크리스트 J로 봐 주셔야 합니다.

## 3. 계획과 다르게 구현한 부분

계획과 어긋난 것은 없고, 계획이 열어 둔 곳과 2회차 검토의 비차단 제안을 이렇게 정했습니다.

- **효과를 더하는 함수 하나**: `UpgradeData.applied()`가 규칙의 사본에 효과를 더해 돌려주고, 게임·T34·스모크가 같은 함수를 씁니다(tech-reviewer 제안).
- **산 직후의 포커스**: 마우스로 누른 버튼은 포커스를 가지므로, 살 것이 남아 있으면 산 뒤에 포커스를 풉니다. T36이 이 경로를 확인합니다(tech-reviewer 제안).
- **안내 문구의 자리**: "다음 날을 연다" 버튼 바로 위에 두었습니다(design-reviewer 제안).
- **봇 설정의 위치**: 스모크에 복사하지 않고 `tests/duel_bots.gd`의 정적 함수로 옮겼습니다. 기존 테스트의 메서드는 그것을 부릅니다.
- **장부의 임대료**: 치료비처럼 적용된 규칙에서 읽습니다. 지금은 임대료를 바꾸는 업그레이드가 없어 값은 같습니다.
- **가진 것의 표시**: 버튼 글 "샀다"에 더해 금색으로 칠했습니다(돈이 모자라 못 사는 것과 구분되게).

## 4. 결정해 주실 것

위임받아 정한 것의 목록입니다. 전부 임시이고, 뒤집고 싶은 것이 있으면 말씀해 주세요.

| 물음 | 정한 것 |
|---|---|
| 2단계를 닫을지 | 닫지 않고 이어 갑니다. 닫는 판정은 아래 순서의 끝에서 요청드립니다 |
| 승리 보상 | 2단계에서는 만들지 않습니다. 이름·양·"승리"의 뜻·평판과의 관계는 정하지 않았습니다 |
| 수치 | 팁 문턱 70, 임대료 60, 치료비 20 그대로 |
| 1단계에서 넘어온 것 | 막기 봇의 정의(결정 29) 확정, 버릇 식히기는 꺼 둠 |
| CLAUDE.md 반영 | 위 네 곳을 고쳤습니다 |
| 칼 수리비, 파산 | 2단계에서 만들지 않습니다. 돈이 모자라면 못 살 뿐입니다 |
| 업그레이드 셋과 값 | 30 / 60 / 90. 기준은 "세 판 평균 85쯤이면 사흘 동안 폐점마다 하나씩" |

| 순서 | 계획 | 내용 |
|---|---|---|
| 1 | 005 (끝남) | 폐점의 업그레이드 구매 |
| 2 | 006 | 접수의 선택: 거절, 맡을 수 있는 수보다 많이 오는 의뢰인, 평판, 부상에 따른 결투 수 감소 |
| 3 | 007 | 조건 협상. 만들지는 006 플레이 뒤에 정함 |
| 4 | 008 | 날마다 다른 의뢰, 저장 |
| — | 2단계 완료 판정 | 사용자 결정 |

따로 여쭙는 것은 둘입니다.

1. **승리 보상의 점수 구조**: 평판과 한 점수로 할지(planner가 기운 안), 평판과 명성을 따로 둘지(예전에 "점수를 새로 만들어"라고 하신 쪽) 정하지 않았습니다. 006에서 평판을 만들 때 정하므로, 그 전에 의견을 주시면 반영합니다.
2. **커밋**: 이번 작업은 커밋하지 않았습니다. 커밋과 푸시(그리고 `main`에도 올릴지)를 말씀해 주세요.

`.tres`의 수치만 바꾸는 요청(값, 효과의 양, 임대료, 시작 소지금)은 바로 반영합니다.

## 5. 다음 작업 제안

- **006 접수의 선택**을 다음 계획으로 제안합니다. 007(협상)과 008(날마다 다른 의뢰)의 순서는 006 보고 때 다시 따집니다. 같은 의뢰 3건의 지겨움이 크게 나오면 008의 데이터 변형을 앞에 둡니다.
- 하루 손익이 +20~+40대로 나오면 값을 내리기보다 시작 소지금(`data/economy_rules.tres`의 `starting_money`)을 먼저 올려 다시 해 보시기를 권합니다(design-reviewer 제안).

## 플레이 체크리스트 J

실행은 저장소 폴더에서 `powershell -ExecutionPolicy Bypass -File play.ps1`입니다. **나흘을 한자리에서 이어서** 해 주세요(조끼를 산 다음 날까지. 중간에 처음 화면으로 나가면 산 것이 사라집니다). 체크리스트 I의 항목도 여전히 유효합니다.

- **먼저**
  - 날마다 폐점의 손익이 대략 얼마였는가(예: +50, +70, +60). 값에 대한 답을 읽으려면 이것이 필요합니다.
  - 며칠째에 무엇을 샀는가. 나흘 안에 조끼를 샀는가.
- **돈**
  - 폐점의 손익이 신경 쓰이게 됐는가. 결투 중에 "이걸 망치면 못 산다"는 생각이 든 적이 있는가.
  - 사고 싶지 않은 것이 있었는가.
  - 값(30 / 60 / 90)은 너무 금방 모이는가, 너무 먼가.
  - 셋을 다 산 뒤에 돈이 다시 숫자로만 남았는가. 며칠째였는가.
  - 소지금이 음수가 된 적이 있는가. 아무 일도 없는 것이 허전했는가.
- **산 것의 효과**
  - 누빈 조끼를 산 다음 날, 결투가 달라진 것을 느꼈는가. 설명 글을 읽고도 샀는가.
  - 조끼를 산 뒤 지기 의뢰가 번거로워졌는가(한 번 더 맞아야 진다). 지기 의뢰의 충족도가 전보다 떨어졌는가.
  - 응접실 의자와 상비약 상자의 효과를 정산 화면에서 알아볼 수 있었는가.
  - "효과는 내일부터"가 헷갈리지 않았는가.
- **화면**
  - 살 것이 있는 날에는 Space로 넘어가지 않는다. 그것이 걸렸는가, 가게를 보게 됐는가.
  - 폐점 화면의 장부와 가게가 한눈에 읽히는가.
- **여전히 묻는 것 (I에서)**
  - 세 판이 전부 바르톨로인 것, 같은 의뢰 3건이 날마다 오는 것이 며칠째부터 지겨운가.
  - 거절하고 싶었던 의뢰가 있었는가.

# 보고서 050: 축제의 멧돼지 — 6단계에서는 하지 않는다

- 계획: `docs/plans/050-festival-boar.md` v1.1. 6단계(콘텐츠), 나눔 039의 050 줄(조건부). 결정 799~802, 새 테스트 없음(합 160 그대로).
- 검토: 1회. 디자인 APPROVE · 기술 APPROVE(비차단 둘 — 엄니 근거의 범위를 좁히기, 내려치기와 올려 막기의 같은 손 — 을 v1.1에 반영).
- 상태(2026-11-28): 문서만 바꿨다. 코드 · `.tres` · 테스트 · 그림 0.

## 1. 한 일

- 판단: 039의 조건("사람의 리그가 네발짐승에 맞는가")이 서지 않는다. ① 엄니를 조준 부위(칼 든 손·팔)로 쓰면 그 노드(`PART_PATHS`)와 판정 상자(`_part_rect`)가 머리를 따라가지 않는다(그림만이면 머리 그림에 그려 우회된다). ② 9칸 부위 표 `AIM_TABLE`이 칼 든 사람을 전제로 한 상수다(R02 · R04와 겹침). ③ 돌진·엄니 훑기·`SPAR`는 기존 셋의 재조합이라 개성 요구에 어긋난다. 일정(이레에 빈 자리 없음)도 겹친다.
- 문서: `docs/DECISIONS.md`(결정 799~802), `docs/BACKLOG.md`(050-1 — 051 뒤 제안, 내려치기와 올려 막기의 차이 (가) · (나), 칼 쪽 부위의 노드 자리를 데이터로), `CLAUDE.md` 9장(6단계 줄에 050), `docs/HANDOFF.md`(지점 "050 끝 → 051", 3번에 판 B-050), 이 보고서.
- 건드리지 않은 것: CLAUDE.md 9장의 "R04 무장 해제·접전 승리"와 4장의 `CLOSE_WIN` 줄, 039 로드맵(승인된 기록).

## 2. 직접 실행해서 확인한 것 / 확인 못 한 것

실행물이 바뀌지 않아 verifier를 부르지 않았다. Godot · 테스트 · 게임을 실행하지 않았다. 확인은 코드 읽기(계획의 근거 절)뿐이며, 리그 쪽(①)은 엄밀하지 않다(결정 800).

## 3. 설계 문서와 다르게 구현한 부분과 이유

- 로드맵(039)의 "색 도형으로 먼저 시험"을 건너뛰었다(결정 800): 막히는 곳이 그림이 아니라 노드 트리와 부위 표라서 코드 읽기로 답이 난다.
- 039의 의뢰 틀(`SPAR`)은 쓰지 않는 쪽으로 제안을 고쳤다: 세 번째 `SPAR`는 개성 요구에 어긋난다. 후보는 `TARGET_PART`(축제 리본).

## 4. 사용자가 결정해야 할 것

그 세션에서는 묻지 않고 메인이 골랐다. 판 B-050(`docs/HANDOFF.md` 3번): 멧돼지를 6단계에서 뺀 것을 받아들이는가. 받아들이지 않으면 계획 050의 제안 ①~⑤가 6단계 안의 새 계획 050a~050c가 되고 051은 뒤로 밀린다.

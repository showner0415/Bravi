## 2. 확인한 것 / 못 한 것

**확인한 것** (실행 없이)

- **F11**: 네 화면에 `get_tree().current_scene`이 0건이고 `day_ui.gd`에만 1건입니다. `Ui.current_session(self)`는 3·3·2·4로 12건입니다. 12곳을 하나씩 따라가 보니, 트리 안에서는 전과 같은 호출로 가고 함수의 나머지 몸은 그대로입니다.
- **테스트에서**: 러너가 붙인 화면은 현재 씬이 아니라 12곳 모두 전처럼 아무 데도 가지 않습니다. 현재 씬인 갈래는 스모크가 실제 씬 전환으로 지납니다.
- **F20**: `saved_day`가 `closing.gd`에 계획대로 5줄 있습니다. 성공 → 보임, 실패 → 숨김, 다시 성공 → 같은 노드가 다시 보이는 흐름을 손으로 따라갔습니다. 016의 T58 "바"(러너에서 붙인 폐점에 줄이 없다)도 그대로입니다.
- **F15·F17**: `_rng`를 쓰는 곳은 0건입니다. `CLIENT_POS`는 `day_ui.gd`에 정의 하나가 있고, 쓰는 곳은 전부 `Ui.CLIENT_POS`입니다.
- **나중 목록**: 적힌 위치의 줄 번호를 019 뒤의 파일에서 Grep으로 채웠습니다. T31이 `money_before`를 읽는 것과 `tests/`의 `_expect` 13개 파일도 확인했습니다.
- **기계적 확인**: 들여쓰기(탭), 타입 추론, 이름 겹침을 봤습니다. 새 테스트가 쓰는 도우미 다섯이 `tests/day_tests.gd`에 있습니다. 바뀐 파일은 계획에 적은 것뿐입니다.

**확인 못 한 것**

- 테스트가 `ALL PASS 65/65`인지, 스모크가 통과하는지(018의 변경도 아직 실행 전입니다).
- 실제로 저장을 실패시켰을 때 "저장했다" 줄이 사라지는지.
- 화면을 넘길 때 의뢰인이 튀지 않는지.

### playtester에게 맡길 확인

게임·테스트·스모크를 띄우는 명령마다 `$env:BRAVI_SAVE_PATH = "user://bravi_playtest_save.json"`을 같은 줄에서 겁니다. **018의 목록 1~12(`docs/reports/018-stage2-checkup.md`)를 먼저 하고, 1번의 기대값만 `ALL PASS 65/65`로 바꿉니다.** 이어서:

13. 폐점에 들어서면 `저장했다 — 끄고 다시 켜도 N일차 아침부터 이어진다`가 보인다. 업그레이드를 하나 사도 그대로 보인다.
14. 저장 실패: 폐점에서(줄이 보이는 때) 사용자 데이터 폴더의 `bravi_playtest_save.json`을 읽기 전용으로 바꾸고(`Set-ItemProperty <경로> -Name IsReadOnly -Value $true`) 업그레이드를 산다 → `저장했다` 줄이 사라지고, 출력에 `저장하지 못했다:` 경고가 있다. 읽기 전용을 풀고 하나 더 산다 → 줄이 다시 보이고 파일의 `money`·`owned`가 바뀌었다. 끝나면 읽기 전용을 풀어 둔다. (바꿔 끼우기가 읽기 전용 파일도 덮어써 실패가 안 생기면 줄이 그대로 남는다. 그 경우는 "실패를 만들지 못했다"로 적는다. 019의 잘못이 아니다.)
15. 의뢰인의 자리: 카운터에서 미끄러져 들어온 의뢰인과 그 판의 정산 화면의 의뢰인이 같은 자리다(화면이 바뀔 때 튀지 않는다).
16. 흥정 주사위의 씨앗: 새로 시작하기를 두 번 해 저장 파일의 `dice_seed`가 서로 다르다(같으면 한 번 더. 두 번 연달아 같으면 실패).
17. 처음 화면의 `연습`, 카운터의 `오늘은 그만`, 폐점의 `처음 화면으로`, `다음 날을 연다`가 평소처럼 화면을 바꾼다(세션 가드).

**가리는 순서** (018과 019를 한 번에 볼 때)

- **테스트 로드 오류**: 파일이 `tidy_tests.gd`면 019, `safety_tests.gd`면 018이다. 스크립트의 파스 오류면 `git diff -- <파일>`(019)을 먼저 보고, 019의 줄이 아니면 `git show 2ffc964 -- <파일>`(018)을 본다.

- **T64**: `closing.gd`의 `refresh_saved_note`다(019).
- **T60~T62**: 018의 가리는 순서 그대로다. 다만 T60 "가"·"다"가 실패하고 원인이 `swallow_arrival_press`면, 019가 바꾼 그 함수의 첫 줄부터 본다.
- **기존 테스트가 새로 실패**:
  - T58 "라"·"바", T33·T36·T39, reputation_tests의 폐점 구매: 019의 12곳(특히 감싸는 꼴의 몸)과 F20을 먼저 본다.
  - T57·T58의 저장 칸: 018의 저장 쓰기를 본다.
- **스모크**: "씬이 바뀌지 않음"이나 멈춤이면 019의 F11(도우미가 현재 씬에서 null을 돌려준다)을 먼저 보고, 그다음 018의 입력 막기를 본다.

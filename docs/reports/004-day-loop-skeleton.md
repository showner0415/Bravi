# 계획 004 보고서: 하루 루프의 뼈대

- 날짜: 2026-11-18
- 계획: `docs/plans/004-day-loop-skeleton.md` (v2)
- 브랜치: `stage2-day-loop`
- 이 파일은 계획 004를 실행한 뒤 사용자에게 한 보고를 그대로 옮긴 것이다. 사용자가 "004 계획 보고서"를 달라고 하면 이 파일의 아래 내용을 보여 준다.
- 보고 뒤의 상태: 사용자는 아직 플레이하지 않았고, "4. 결정해 주실 것"의 1~6번에 답하지 않았다. 7번(커밋)은 같은 날 커밋하고 푸시했다.

계획 004(하루 루프의 뼈대)를 끝까지 실행했습니다. 게임을 켜서 "가게를 연다"를 누르면 의뢰 3건 → 폐점 → 다음 날까지 이어집니다. 작업은 새 브랜치 `stage2-day-loop`에 있습니다.

## 1. 한 일

- **하루 상태와 장부**: 단계 전환, 보수 계산, 폐점 지출을 화면과 분리된 로직으로 만들었습니다 (`scripts/economy/day_state.gd`, `economy_rules.gd`, `day_data.gd`, `data/economy_rules.tres`, `data/days/day_01.tres`).
- **결투의 하루 모드**: 하루 중의 결투는 한 번뿐입니다. R과 Esc를 듣지 않고, 끝난 뒤 Space/Enter로 정산에 갑니다 (`duel_scene.gd`, `result_panel.gd`, `duel_hud.gd`, `game_session.gd`).
- **화면 넷**: 처음 화면, 카운터, 정산, 폐점 (`scripts/title.gd`, `scripts/commission/counter.gd`, `scripts/economy/settlement.gd`, `closing.gd`, 씬 4개). 메인 씬을 처음 화면으로 바꿨습니다.
- **연습**: 기존 의뢰 선택 화면은 처음 화면의 "연습"으로 남겼고, Esc로 처음 화면에 돌아갑니다.
- **테스트**: T28~T33(`tests/day_tests.gd`)과 하루 통째 스모크(`tests/day_smoke.gd`, `day_smoke.tscn`, `run_smoke.ps1`)를 더했고, T0에 Space/Enter 액션 검사를 붙였습니다.
- **기록**: `docs/DECISIONS.md`에 결정 31~41과 실행 중에 정한 것을 적었습니다.

정산 규칙(전부 임시값)은 다음과 같습니다.

| 항목 | 규칙 |
|---|---|
| 기본 보수 | 의뢰의 기본 보수 × 충족도% |
| 팁 | 충족도 70을 넘는 만큼에 비례 (70 이하면 0) |
| 치료비 | 유효타를 맞고 끝난 결투마다 20, 폐점 때 지출 |
| 임대료 | 하루 60 |

완벽한 하루는 수입 185, 손익 +105입니다.

## 2. 확인한 것 / 못 한 것

**확인한 것**
- 테스트: `RESULT: OK (ALL PASS 34/34, error lines 0, warning lines 0)`
- 스모크: `DAY SMOKE OK (씬 16개를 순서대로 지남)`, `RESULT: OK`. 축소 없이 돌았고 세 번 연속 통과했습니다.
  - 처음 화면 → (카운터 → 결투 → 정산) 세 번 → 폐점 → 2일차 카운터까지 실제 씬 전환으로 지났습니다.
  - 하루 결투 중 R·Esc가 무시되는 것, 끝나기 전의 Space가 무시되는 것, 끝난 뒤 Space로 정산에 가는 것을 실제 키 입력으로 봤습니다.
  - 장부: 입력 없이 세 판을 져서 수입 0, 임대료 60, 치료비 60, 손익 −120이 맞게 나왔습니다.
- 씬 직접 실행: 메인 씬, 카운터, 정산, 폐점, 의뢰 선택, 결투를 각각 띄워 오류 줄이 0이었습니다.
- 스크린샷: 다섯 화면 모두 글자가 잘리거나 겹치지 않습니다. 가장 긴 지기 의뢰의 대사도 말풍선에 들어갑니다.

**확인 못 한 것**
- 스모크의 결투는 전부 입력 없이 진 판입니다. 돈이 들어온 정산과 폐점 화면은 스크린샷으로 보지 못했고, 숫자만 테스트로 확인했습니다.
- 마우스로 버튼을 누르는 것, Space를 누른 채 화면이 두 개씩 넘어가는지는 사람 손으로만 확인됩니다.
- 하루로 느껴지는지, 돈이 신경 쓰이는지 같은 재미 판단은 아래 체크리스트로 봐 주셔야 합니다.

## 3. 계획과 다르게 구현한 부분

- **공용 도우미 파일**: 화면 넷이 함께 쓰는 `scripts/day_ui.gd`를 만들었습니다. 계획의 파일 목록에 없던 파일입니다.
- **스모크 범위 확대**: 계획의 12개 씬에 빠져나오는 길과 연습 경로를 더했습니다 ("오늘은 그만" → 처음 화면 → 연습 → Esc → 처음 화면 → Enter로 새 하루).
- **의뢰 선택 화면 제목**: "연습 — 의뢰를 골라 결투 (Esc: 처음 화면)"으로 바꿨습니다.
- **잘못 열린 화면**: 카운터·정산·폐점이 하루 상태 없이 열리면 배경만 그리고 처음 화면으로 돌아갑니다.
- **Space/Enter 액션**: 엔진 기본 액션이 테스트에서도 있어서 대체 액션은 만들지 않았습니다.
- **채택하지 않은 제안**: tech-reviewer의 "씬 직접 실행 때 돌아갔다는 줄을 출력"은 넣지 않았습니다. 그 경로는 오류 줄 0으로만 확인했습니다.

정산 때 의뢰인이 하는 말은 충족도 구간별로 네 가지입니다. 세 의뢰인 모두에게 어색하지 않은지 봐 주세요.

| 충족도 | 문구 |
|---|---|
| 0 | …부탁드린 건 이게 아니었는데요. 이래서는 보수를 드릴 수가 없어요. |
| 1~70 | 부탁드린 대로는 아니었지만, 애써 주신 만큼은 쳐 드릴게요. |
| 71~99 | 거의 부탁드린 그대로였어요. 고맙습니다, 조금 더 얹었어요. |
| 100 | 부탁드린 그대로예요! 더 바랄 게 없네요. 넉넉히 넣었으니 받아 주세요. |

## 4. 결정해 주실 것

1. **2단계 완료 여부**: 완료 기준 "하루 3의뢰를 끝까지 플레이 가능"은 글자 그대로는 채워졌습니다. 여기서 닫을지, 아래 5번에서 무엇을 더 만들지 플레이 뒤 정해 주세요.
2. **승리 보상**: 이번에는 만들지 않았습니다. 검토자가 임시값 구현을 막았습니다. 지금 규칙에서는 "이겼다"가 "조건을 채우는 타격이 들어갔다"와 같은 사건이라, 머리를 쳐 40점인 첫 피에도 "승리"가 뜨기 때문입니다. 답이 없으면 다음 계획에서도 만들지 않습니다.
   - **이름과 양**: "명예"와 "명성" 중 무엇인지, 한 번에 얼마나 오르는지.
   - **"승리"의 뜻**:
     - (가) 내 유효타로 끝나면 승리. 규칙은 그대로지만 사실상 "의뢰를 해냈다"와 같습니다.
     - (나) 조건을 채운 뒤에도 싸워서 이기면 덤. 말씀하신 뜻에 가장 가깝지만 결투 종료 규칙을 바꾸는 별도 계획이 필요하고, 남은 계획의 순서가 달라집니다.
     - (다) 지금의 3종에는 해당 없음. 승패와 무관한 새 의뢰가 생길 때 만듭니다.
   - **평판과의 관계**: 가게 별점(평판)과 같은 점수인지 별개인지.
3. **수치**: 팁 문턱 70, 임대료 60, 치료비 20. 값만 바꾸는 요청은 바로 반영합니다.
4. **돈에 대한 답을 읽는 법**: 지금은 돈을 쓸 곳이 없고 음수여도 아무 일이 없습니다. "손익이 신경 쓰이지 않는다"면 숫자가 납득되지 않아서인지, 쓸 곳이 없어서인지 가려서 알려 주세요.
5. **1단계에서 넘어온 것**: 판 길이 기준이 가리키는 플레이가 "큰 베기에는 막기를 다시 올리기"로 바뀐 것의 확인, 버릇 식히기(지금 꺼짐)를 켤지.
6. **CLAUDE.md 반영(제안)**: 5장에 지금 만든 범위, 8장에 `data/days/`와 `data/economy_rules.tres`.
7. **커밋**: 이번 작업을 커밋할지 말씀해 주세요.

## 5. 다음 작업 제안

2단계에 남은 묶음은 넷이고, 순서는 플레이 뒤에 정하시면 됩니다.

- **접수의 선택**: 거절, 조건 협상, 평판.
- **폐점의 선택**: 업그레이드, 칼 수리비, 부상에 따른 남은 의뢰 수 감소, 돈이 바닥났을 때의 결과. 지기 의뢰는 잘 해내도 다치므로 부상을 따로 다룰지도 여기서 정합니다.
- **날의 진행**: 날마다 다른 의뢰, 저장.
- **승리 보상**: 위 2번의 답에 달려 있습니다.

세 판이 모두 같은 상대(바르톨로)라서, 둘째 판부터 김이 빠지는지는 따로 봐 주세요.

## 플레이 체크리스트 I

실행은 `C:\godot\Godot_v4.7.2-stable_win64.exe --path C:\godot\bravi`입니다. 하루를 두세 번 해 보시면 됩니다.

- **이어지는가**
  - 처음 화면 → 세 의뢰 → 폐점 → 다음 날이 막히는 곳 없이 넘어가는가.
  - Space를 누르고 있다가 화면이 두 개씩 넘어간 적이 있는가.
- **하루의 리듬**
  - 하루에 걸린 시간. 세 판을 연달아 하는 것이 기분 좋은가, 지치는가.
  - 결투 사이의 화면 셋(결과 패널, 정산, 다음 의뢰인)이 길게 느껴지는가.
  - 채점표(결과 패널)가 의뢰인 반응보다 먼저 뜬다. 결과 패널을 건너뛰고 정산에 내역을 함께 싣는 편이 나은가.
  - 세 판이 전부 바르톨로다. 둘째 판부터 김이 빠지는가.
- **한 번뿐인 결투**
  - 다시 할 수 없다는 것이 긴장을 만드는가, 억울한가. 연습으로 가고 싶어졌는가.
- **돈**
  - 정산의 숫자를 보고 왜 그만큼 받았는지 알 수 있는가.
  - 깃털에서 몸을 한 번 스쳐 팁이 깎이는 것이 아까운가.
  - 첫 피에서 머리를 쳤을 때의 보수(30 중 12, 팁 없음)가 납득되는가.
  - 폐점의 손익이 신경 쓰이는가.
  - 임대료 60은 빡빡한가, 너그러운가.
  - 지기는 잘 해내도 치료비 20이 든다. 그래도 맡을 만한가.
- **카운터**
  - 사연을 읽게 되는가, 넘기게 되는가. Space를 누르던 손이 그대로 "맡는다"를 눌러 버린 적이 있는가.
  - 둘째 날에도 사연을 읽었는가.
  - 대사의 힌트가 결투에서 쓸모 있었는가.
  - 거절하거나 값을 더 부르고 싶었던 의뢰가 있었는가.
  - 정산 때 의뢰인의 한 줄이 어색한 의뢰가 있었는가.
